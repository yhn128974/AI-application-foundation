4. 结束节点输出大模型整理后的内容。
5. 运行测试，输入一段不少于 50 字的文本。

### 2. 给工作流增加空输入判断

要求：

1. 在基础文本处理工作流中加入选择器节点。

### 3. 创建一个旅游规划工作流

### 5. 创建一个意图识别分流工作流

### 6. 创建一个文档提取工作流

### 简答题参考答案

1. 智能体不是普通聊天机器人，因为普通聊天机器人主要是根据用户问题生成回答，而智能体还可以围绕目标进行判断、拆分步骤、调用工具并完成任务。例如普通聊天机器人只能告诉你“可以查天气”，智能体可以直接调用天气插件查出结果，再整理成建议。

2. 插件的作用是给智能体增加外部能力。大模型本身主要负责理解和生成文本，插件可以让它联网搜索、查天气、读取文档、识别图片、查询数据等。例如联网搜索插件可以查询实时信息，文档提取插件可以读取 PDF 或 Word 内容。

3. 不建议一口气搭完所有节点再测试，是因为节点越多，出错位置越难定位。正确做法是每加一个关键节点就运行一次，确认输入、输出和变量传递都正确，再继续往后搭建。

4. 选择器节点适合明确条件判断，例如输入是否为空、某个字段是否等于某个值。意图识别节点适合语义分类，例如判断用户是想旅游规划、文档分析还是普通聊天。简单说，选择器更像代码里的 if / else，意图识别更像让模型理解用户意图后分类。

5. `classification_id` 通常只是意图分类结果，例如 1、2、3，它用于决定流程走哪条分支。它不是用户原始问题。如果把它传给大模型，大模型只会看到一个编号，无法知道用户真正想问什么。后续生成回答时，应该继续传用户原始输入。

6. 输入节点适合解决信息缺失问题。例如用户说“帮我规划旅游路线”，但没说去哪里，工作流可以通过输入节点追问“你想去哪个城市？”，再把用户补充的城市传给后续节点。

7. 工作流名称和描述要写清楚，是因为后续智能体选择工具时，需要根据工具名称和描述判断什么时候调用它。名称模糊会导致自己维护困难，也会导致智能体不容易选对工具。

8. 使用联网搜索插件时要查看输出字段，因为不同插件返回的数据结构不同，有的字段是标题，有的字段是链接，有的字段才是真正内容。如果字段选错，最终输出可能为空、杂乱或不是用户需要的信息。

9. 文档提取插件在求职类 AI 应用中可以用于读取简历内容，提取姓名、学历、技能、项目经验、工作经历等信息。提取成文本后，还可以交给大模型继续做简历优化、岗位匹配、面试题生成。

10. 如果智能体没有调用添加的工作流，可以优先检查：工作流是否已经发布；工具名称和描述是否清楚；智能体提示词是否说明什么时候调用该工具；用户测试问题是否确实触发该工具场景；工作流本身是否能单独运行成功。

### 操作题参考答案

#### 1. 创建基础文本处理工作流

参考步骤：

1. 创建工作流，名称可以写成 `text_summary_workflow`。
   这样命名的作用是让自己和智能体都能看出这个工作流用于文本整理。

2. 在开始节点保留或创建文本变量 `input`。
   `input` 用来接收用户输入的原始文本，是整个流程的数据入口。

3. 添加大模型节点，并在提示词中写：

```text
请将下面这段内容整理成三条要点。
要求：
1. 每条要点单独成行。
2. 语言简洁。
3. 不要添加原文没有的信息。

用户输入：
{{input}}
```

说明：

1. `{{input}}` 的作用是把开始节点接收到的用户文本传给大模型。
2. “三条要点”限制了输出结构，便于检查结果是否稳定。
3. “不要添加原文没有的信息”用于减少模型乱编。

4. 在结束节点选择大模型节点的正式输出字段。
   不要选择推理过程字段，也不要选择空字段。

5. 运行测试，输入一段文本，检查最终是否输出三条要点。

#### 2. 增加空输入判断

参考步骤：

1. 在开始节点后添加选择器节点。
   选择器的作用是先判断用户有没有输入内容。

2. 设置条件：

```text
如果 input 为空
```

说明：

1. 这个条件用于拦截无效输入。
2. 如果用户什么都没写，直接进入大模型会浪费资源，也容易得到无意义回答。

3. 空输入分支连接到输出节点，输出：

```text
请输入需要整理的内容。
```

4. 非空分支连接到大模型节点。
   这样只有用户真正输入内容时，才会让模型整理文本。

5. 分别测试两次：

1. 第一次不输入内容，应该提示“请输入需要整理的内容”。
2. 第二次输入正常文本，应该进入大模型并输出三条要点。

#### 3. 创建旅游规划工作流

参考步骤：

1. 创建工作流，名称建议为 `travel_plan_workflow`。
   这个名称能清楚表达“旅游规划”用途。

2. 开始节点接收用户输入 `input`。
   用户可以输入目的地、天数、预算、偏好等信息。

3. 添加联网搜索插件。
   将搜索关键词设置为用户输入 `input`。
   这样插件会根据用户需求查找相关信息。

4. 添加大模型节点，把搜索结果和用户输入一起传入。
   提示词可以写：

```text
你是一个旅游规划助手。
请结合用户需求和搜索结果，生成一份简洁实用的旅游建议。

用户需求：
{{input}}

搜索结果：
{{search_result}}

输出格式：
1. 行程安排
2. 推荐理由
3. 注意事项

要求：
1. 不要编造搜索结果中没有的信息。
2. 如果信息不完整，要说明可以继续补充哪些信息。
```

说明：

1. `{{input}}` 保留用户原始需求。
2. `{{search_result}}` 表示搜索插件返回的结果，实际变量名要按你的节点输出选择。
3. 固定输出格式能让结果更适合直接阅读。

5. 结束节点输出大模型整理后的旅游建议。

#### 4. 增加目的地补充

参考步骤：

1. 在旅游规划工作流中加入一个判断逻辑。
   可以先用大模型或意图判断用户是否提供了目的地。

2. 如果没有目的地，添加输入节点追问：

```text
你想去哪个城市旅行？
```

3. 输入节点变量命名为 `city`。
   这样命名比继续叫 `input` 更清楚，也能避免变量冲突。

4. 在后续大模型节点中添加 `city` 变量，并在提示词中引用：

```text
用户补充的目的地城市：
{{city}}
```

说明：

1. 只创建 `city` 变量还不够，后续节点必须接收它。
2. 接收变量后还要在提示词中引用，模型才知道这个城市是什么。

5. 测试两种输入：

1. “帮我规划一个周末游”：应该追问目的地。
2. “帮我规划一个深圳周末游”：应该直接进入规划流程。

#### 5. 创建意图识别分流工作流

参考步骤：

1. 添加意图识别节点，设置三个意图：

```text
旅游规划：用户想安排旅行路线、景点、美食、行程。
文档分析：用户想上传或分析文档、简历、PDF、Word。
其他问题：不属于以上两类的问题。
```

说明：

1. 意图描述越清楚，分类越稳定。
2. 不要只写“旅游”“文档”“其他”，这样模型判断依据太少。

2. 根据意图识别结果连接不同分支。

3. 旅游规划分支连接旅游规划工作流或旅游规划大模型节点。

4. 文档分析分支输出提示：

```text
请上传需要分析的文档，我会帮你提取关键信息。
```

5. 其他问题分支连接普通大模型回答节点。

6. 注意：后续大模型回答时仍然传用户原始输入 `input`。
   `classification_id` 只用于分支判断，不用于生成具体答案。

#### 6. 创建文档提取工作流

参考步骤：

1. 创建工作流，名称建议为 `doc_extract_workflow`。

2. 在开始节点创建文件变量，例如 `doc_file`。
   这个变量用于接收用户上传的文档。

3. 添加文档提取或链接读取插件。
   将插件的文件地址或文档输入参数绑定到 `doc_file`。

4. 查看插件示例和运行日志，找到真正的文档内容字段。
   常见字段可能叫 `content`、`pdf_content` 或类似名称，具体以插件返回为准。

5. 添加大模型节点，提示词可以写：

```text
请根据下面的文档内容，提取关键信息。

文档内容：
{{doc_content}}

请按以下格式输出：
1. 文档主题
2. 核心内容
3. 可以继续追问的问题

要求：
1. 只根据文档内容回答。
2. 如果文档中没有出现某项信息，请写“文档中未明确提到”。
```

说明：

1. `{{doc_content}}` 要绑定到插件提取出来的正文内容。
2. “只根据文档内容回答”用于减少模型补充无依据内容。
3. “未明确提到”能避免模型乱编。

6. 使用脱敏文档测试。
   不要上传真实身份证号、手机号、合同金额、公司内部资料等敏感信息。

#### 7. 搭建多功能智能体

参考步骤：

1. 先确认至少两个工作流已经单独运行成功并发布。
   例如：旅游规划工作流、文档提取工作流。

2. 创建智能体，名称可以写成“学习与资料处理助手”。
   名称要让用户知道它大概能做什么。

3. 编写智能体职责说明：

```text
你是一个学习与资料处理助手。
你可以根据用户需求选择合适工具：
1. 当用户需要旅游规划、路线建议、景点安排时，调用旅游规划工作流。
2. 当用户上传文档并希望提取、总结或分析内容时，调用文档提取工作流。
3. 当用户只是普通提问时，直接用清楚、简洁的语言回答。

要求：
1. 不要编造工具没有返回的信息。
2. 如果用户信息不足，先追问关键缺失信息。
3. 回答要结构清晰，方便用户继续操作。
```

说明：

1. 第 1 条告诉智能体旅游类需求用哪个工具。
2. 第 2 条告诉智能体文档类需求用哪个工具。
3. 第 3 条避免所有问题都强行调用工具。
4. “不要编造”用于降低幻觉。
5. “信息不足先追问”能提升用户体验。

4. 添加工具，选择已经发布的工作流。
   如果找不到工作流，优先检查是否发布成功。

5. 设置开场白，例如：

```text
你好，我可以帮你规划旅行、提取文档重点，也可以回答学习中的问题。
```

6. 设置预设问题，例如：

```text
帮我规划一个深圳周末游
```

```text
我上传一份文档，你帮我提取重点
```

7. 预览测试三类问题：

1. 旅游规划：检查是否调用旅游规划工作流。
2. 文档分析：检查是否提示上传文档或调用文档提取工作流。
3. 普通闲聊：检查是否直接回答，而不是乱调用工具。
