### 简答题参考答案

1. 知识库适合存放文档资料，用来检索和问答，例如公司制度 PDF、课程讲义、产品说明书。数据库适合存放结构化数据，用来增删改查，例如学生签到表、员工绩效表、订单表。

2. 大模型需要 RAG，是因为模型不知道企业内部资料，知识可能过时，也可能在不确定时编造。RAG 通过先检索资料、再生成答案，让模型回答更有依据，也便于资料更新。

3. 分段太大时，检索结果不精准，模型会读到很多无关内容；分段太小时，上下文不完整，模型可能只看到半句话，回答容易断章取义。合适的分段能让召回内容既精准又完整。

4. 全文检索主要按关键词匹配，适合用户问题和文档原文用词接近的情况。语义检索主要按意思匹配，即使用户换一种说法也可能找到相关内容。混合检索结合两者，通常更稳。

5. 知识库检索结果通常是原始片段，可能零散、生硬、不适合直接给用户看。大模型润色可以把片段整理成自然语言，按用户问题组织答案，并在资料不足时说明限制。

6. “知识库优先，联网搜索兜底”的思路是：用户提问后先查自己的知识库，如果有有效结果，就以知识库内容为主回答；如果知识库没有结果，再调用联网搜索补充信息；最后统一交给大模型整理成自然回答。

7. 数据库需要明确字段和值才能查询，而用户输入通常是自然语言。例如“帮我查张三的绩效”不能直接作为查询条件，需要先抽取出姓名“张三”，再用 `name == 张三` 去查询。

8. 更新和删除会改变数据库中的数据，如果条件不准确，可能改错或删错记录。真实业务中常用多个条件联合定位，例如姓名加工号，删除前还需要确认，甚至使用软删除而不是直接物理删除。

9. ASR 是语音转文字，例如把面试录音转成文字，方便后续分析。TTS 是文字转语音，例如把广告文案生成配音，或让智能客服用语音回复用户。

10. 视频生成通常成本高、耗时长，并且复杂动作、手部细节、物理交互容易出错。它更适合作为创意生成和初稿探索，不能承诺一次生成一定完美，真实工作中通常要多次生成、筛选和后期处理。

### 操作题参考答案

#### 1. 创建知识库问答工作流

参考步骤：

1. 在资源库中新建知识库。
   这样做是为了把课程资料或说明文档存入平台，让后续工作流可以检索这些资料。

2. 上传一份资料，例如课程讲义、产品说明书或大模型发展史文档。
   资料应尽量结构清晰，标题和段落明确，这样分段效果更好。

3. 配置解析和分段。
   分段的作用是把长文档切成适合检索的小片段。建议先用自动分段，预览效果后再决定是否调整。

4. 创建工作流，开始节点接收用户问题 `input`。
   `input` 是用户问题的入口，后面知识库检索节点要用它作为查询内容。

5. 添加知识库检索节点，把 `input` 绑定为检索问题。
   这样用户问什么，系统就用什么去知识库里找相关片段。

6. 添加大模型润色节点，提示词可参考：

```text
你是一个资料问答助手。
请根据知识库检索结果回答用户问题。
如果资料中没有相关内容，请明确说明“当前资料中没有找到相关答案”。
不要编造资料中没有的信息。

用户问题：
{{input}}

知识库检索结果：
{{knowledge_result}}
```

说明：

1. `{{input}}` 表示用户原问题。
2. `{{knowledge_result}}` 表示知识库返回内容，实际变量名按你的节点输出选择。
3. “不要编造”是为了减少模型幻觉。

7. 结束节点输出润色节点的正式回答。

8. 测试两个问题：

1. 资料中有答案的问题：应该能根据资料回答。
2. 资料中没有答案的问题：应该提示资料不足，不应乱编。

#### 2. 优化知识库检索效果

参考步骤：

1. 先使用默认参数测试一次。
   记录返回内容是否准确、是否完整。

2. 调整召回数量。
   如果答案漏信息，可以适当增加召回数量；如果回答混乱，可以减少召回数量。

3. 调整最小匹配度。
   如果召回很多无关内容，可以提高匹配度；如果经常没有结果，可以降低匹配度。

4. 对比结果。
   不要只看最终回答，还要看检索节点返回了哪些片段。

5. 参考结论：

```text
如果资料质量较好、用户问题明确，可以使用混合检索，召回数量 5 左右，匹配度 0.7 左右作为起点。
如果实际效果不好，再根据召回内容进行调整。
```

说明：

这不是唯一答案。参数调整要看资料质量、问题表达和实际召回结果。

#### 3. 搭建知识库加联网搜索兜底流程

参考步骤：

1. 在原有知识库问答工作流中增加联网搜索插件。
   联网搜索用于处理知识库没有覆盖的问题。

2. 增加选择器节点或判断逻辑。
   判断知识库检索结果是否为空或明显不足。

3. 如果知识库有结果，走知识库分支。
   这样能优先使用自己上传的可靠资料。

4. 如果知识库无结果，走联网搜索分支。
   这样能避免用户一问资料外内容，系统就完全无法回答。

5. 最后统一进入大模型润色节点。
   提示词可以写：

```text
请根据以下信息回答用户问题。
优先使用知识库内容。
如果知识库为空或不足，再参考联网搜索结果。
回答中请说明主要依据来自知识库还是联网搜索。
不要编造没有依据的信息。

用户问题：
{{input}}

知识库内容：
{{knowledge_result}}

联网搜索结果：
{{web_result}}
```

说明：

1. 统一润色可以保证输出风格一致。
2. 说明信息来源可以提升可信度。
3. 联网搜索是兜底，不应覆盖明确的内部资料。

#### 4. 创建绩效数据库并导入数据

参考步骤：

1. 在资源库中新建数据库。

2. 创建数据表，字段建议：

```text
work_code：工号，字符串类型
name：姓名，字符串类型
performance_level：绩效等级，字符串类型
```

说明：

1. 工号不参与数学计算，因此用字符串更合适。
2. 字符串可以保留前导 0，也能避免格式被自动改动。

3. 准备测试数据，例如：

```text
work_code,name,performance_level
1001,张三,A
1002,李四,B
1003,王五,C
1004,赵六,A
1005,钱七,B
```

说明：

这是测试数据，目的是验证流程，不代表正式生产数据。

4. 使用批量导入功能导入数据。

5. 导入后在数据表中检查是否出现 5 条记录。

6. 如果导入失败，检查：

1. 表头是否和字段名一致。
2. 字段类型是否匹配。
3. 文件格式是否支持。

#### 5. 搭建绩效查询工作流

参考步骤：

1. 创建工作流，开始节点接收用户输入 `input`。

2. 添加人名抽取大模型节点。
   提示词可参考：

```text
请从用户输入中提取要查询绩效的姓名。
如果能提取到姓名，只返回姓名。
如果没有姓名，只返回“无”。

用户输入：
{{input}}
```

说明：

1. 这个节点只做一件事：提取姓名。
2. 输出越简单，后面数据库查询越稳定。

3. 添加数据库查询节点。
   查询条件设置为：

```text
name 等于 人名抽取节点的输出
```

说明：

数据库不能理解自然语言，所以要用抽取出的姓名作为查询条件。

4. 添加润色节点。
   提示词可参考：

```text
请根据数据库查询结果回答用户问题。
如果查询结果为空，请说明没有找到对应记录。
如果查询到结果，请用自然语言说明工号、姓名和绩效等级。

用户问题：
{{input}}

数据库查询结果：
{{db_result}}
```

5. 测试：

1. “查张三的绩效”：应返回张三对应信息。
2. “查不存在的人”：应提示没有找到记录。

#### 6. 搭建绩效新增、修改、删除流程

参考步骤：

1. 添加意图识别节点。
   设置三个意图：

```text
新增数据：用户想添加一条新的绩效记录。
修改数据：用户想修改已有绩效记录。
删除数据：用户想删除已有绩效记录。
```

说明：

意图描述要写清楚，避免用户说“改一下”时系统分不准。

2. 新增分支：

先用信息抽取节点提取姓名、工号、绩效等级，再绑定到新增数据节点。

如果缺少任一字段，先提示用户补充，不要直接新增。

3. 修改分支：

先抽取姓名、工号、新绩效等级。

更新节点中要分清：

```text
定位条件：name 等于 抽取姓名，并且 work_code 等于 抽取工号
更新字段：performance_level 改为 新绩效等级
```

说明：

定位条件用于找到要改哪条记录，更新字段用于说明改成什么。

4. 删除分支：

先抽取姓名和工号。

删除节点中设置：

```text
name 等于 抽取姓名，并且 work_code 等于 抽取工号
```

说明：

删除必须精确定位。只用姓名容易误删重名人员。

5. 每个分支后都接一个输出节点。
   输出要告诉用户操作是否完成，以及操作了哪条记录。

#### 7. 搭建多模态小工作流

参考步骤一：文生图

1. 创建工作流，开始节点接收文本提示词。
2. 添加图像生成插件。
3. 把用户提示词传给图像生成插件。
4. 设置模型、分辨率等参数。
5. 结束节点输出图片结果。

提示词示例：

```text
生成一张写实风格的金毛犬图片，背景是雪地，金毛正在奔跑玩雪，阳光柔和，画面清晰，不要出现文字和水印。
```

说明：

提示词包含主体、场景、风格、光线和限制，生成结果通常更稳定。

参考步骤二：ASR

1. 创建工作流，开始节点输入类型设置为音频。
2. 添加语音识别插件。
3. 把音频文件传给插件。
4. 输出识别文本。
5. 后接大模型节点补充标点和段落。

润色提示词示例：

```text
请将下面的语音识别结果整理成通顺文本。
要求：
1. 补充合理标点。
2. 按语义分段。
3. 不改变原意。

识别结果：
{{asr_text}}
```

说明：

ASR 常常识别出连续文本，大模型润色可以让它更适合阅读。

参考步骤三：TTS

1. 创建工作流，开始节点接收文本。
2. 添加语音合成插件。
3. 设置音色、语速、情绪等参数。
4. 输出音频链接。

说明：

TTS 插件通常对文本长度有要求，运行前要查看插件说明。
