无论是通过 **API 接口调用** 现成的大模型，还是在进行 **模型微调（Fine-tuning）**，这三种角色都承载着相同的语义，但在具体的操作流程和数据结构上有所不同。

## 一、 在 API 接口调用中如何使用

在调用大模型 API（如 OpenAI、Anthropic 或国内的通义千问、文心一言等 Chat 接口）时，你需要将对话组织成一个 **消息数组（Array of Messages）**。

### 1. 单轮对话（Single-turn）

如果你只需要大模型回答一个独立的问题，通常传入一个 `system` 消息和一个 `user` 消息，模型会返回一个 `assistant` 消息。

- **调用代码示例（Python 伪代码）：**

Python

```
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "system", "content": "你是一位专业的心理咨询师，语气要温柔、包容。"},
        {"role": "user", "content": "我最近工作压力很大，总是失眠怎么办？"}
    ]
)
# 获取大模型的回复（即 assistant 的内容）
print(response.choices[0].message.content)
```

### 2. 多轮对话（Multi-turn）

大模型本身是**无状态（Stateless）\**的，它不记得你上一句说了什么。为了实现连续对话，你必须\**把历史对话完整地传回给 API**。此时，你需要手动将之前模型返回的内容作为 `assistant` 角色拼接到数组中。

- **拼接后的请求格式：**

JSON

```
[
  {"role": "system", "content": "你是一位专业的心理咨询师，语气要温柔、包容。"},
  {"role": "user", "content": "我最近工作压力很大，总是失眠怎么办？"},
  {"role": "assistant", "content": "听到你这么说，我能感受到你现在的疲惫。失眠往往是身体在提醒我们需要放松...建议你可以试着..."} // 这是上一次 API 返回给你的内容
  {"role": "user", "content": "好的，那我今晚试试冥想。如果还是睡不着呢？"} // 用户的新提问
]
```

## 二、 在模型微调（Fine-tuning）中如何使用

微调的目的是为了让模型学习**特定的任务、语气、回复格式或专业知识**。在微调时，你需要准备成百上千条高质量的“模拟对话数据”，通常保存为 `.jsonl`（JSON Lines）格式。

在微调数据集中，这三个角色的使用核心逻辑是：**利用 `system` 和 `user` 作为输入（Prompt），训练模型去预测并生成 `assistant` 的内容。**

### 1. 微调的数据结构

每一行（即每一个训练样本）都必须是一个完整的对话闭环。

- **微调数据集示例（`dataset.jsonl`）：**

JSON

```
{"messages": [{"role": "system", "content": "你是一个客服机器人，只能回答关于退换货政策的问题。"}, {"role": "user", "content": "我的衣服尺码买大了，可以换吗？"}, {"role": "assistant", "content": "您好！在商品不影响二次销售的前提下，我们支持7天内无理由退换货。您可以进入订单详情页申请换货。"}]}
{"messages": [{"role": "system", "content": "你是一个客服机器人，只能回答关于退换货政策的问题。"}, {"role": "user", "content": "你们今天几点下班？"}, {"role": "assistant", "content": "抱歉，我只能协助您处理退换货相关的问题。关于营业时间，建议您咨询人工客服。"}]}
```

### 2. 微调时的注意事项

- **Assistant 是“标准答案”：** 在微调过程中，损失函数（Loss）通常只计算 `assistant` 部分。模型会学习在遇到前文的 `system` 和 `user` 时，如何说出像 `assistant` 一样的完美回答。因此，**`assistant` 的内容质量直接决定了微调的效果**。

- **System 的一致性：** 如果你希望微调后的模型在以后使用时都具备某种特定人设，那么在微调数据集中，每一条数据的 `system` 最好保持高度一致。

- **模拟多轮微调：** 如果你希望模型学会处理复杂的多轮对话，你的单个微调样本里也可以包含多轮交互：

  JSON

  ```
  {"messages": [{"role": "system", "content": "..."}, {"role": "user", "content": "问1"}, {"role": "assistant", "content": "答1"}, {"role": "user", "content": "问2"}, {"role": "assistant", "content": "答2"}]}
  ```

```
## 总结：两者的核心区别

| 维度 | API 接口调用 | 模型微调（Fine-tuning） |
| :--- | :--- | :--- |
| **主要目的** | **消费**模型：利用现有模型获取实时生成的回复。 | **塑造**模型：改变模型的内在权重，使其符合特定行为模式。 |
| **`assistant` 的身份** | 由**大模型实时生成**的输出结果，程序负责接收它。 | 由**人类专家提前写好**的“完美标准答案”，用于训练模型。 |
| **数据规模** | 每次调用只传当前的一条或一组历史上下文。 | 需要准备包含几百到几万条完整对话的数据集。 |
```
