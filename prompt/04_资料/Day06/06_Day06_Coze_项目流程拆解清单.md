# Day06 Coze 项目流程拆解清单

## 一、整体项目链路

AI 面试助手不是一个单节点功能，而是一条业务链。

| 阶段 | 做什么 | 为什么需要 |
|---|---|---|
| 用户提交材料 | 用户上传简历或录音，也可以由系统管理员批量提交材料 | 明确系统要处理的原始输入 |
| 路由识别需求 | 判断是简历评估、录音分析、面试题生成还是批量处理 | 避免一个智能体承担所有任务 |
| 业务模块执行 | 对应 Agent 执行具体任务 | 让每个模块职责清楚 |
| 数据和知识支撑 | 使用数据库、知识库、ASR、RAG、联网搜索等能力 | 让结果有依据，不靠大模型硬编 |
| 输出报告 | 生成可读的评估报告、分析报告或面试题 | 用户真正需要的是结论和建议 |

## 二、简历评估全节点清单

简历评估模块不是一个单节点流程，而是一条由数据准备、内容分块、并行评估、项目循环、结果整合组成的完整链路。

| 节点 | 节点名称 | 输入 | 输出 | 作用 |
|---|---|---|---|---|
| N0 | 开始 | 简历文件 `resume` | 文件对象或 URL | 接收用户上传简历 |
| N1 | 简历文字提取 | `resume` | `pdf_content` 或 `content` | 把文件变成文本 |
| N2 | 违禁词查询 | 查询条件 | `outputList` | 获取违禁词列表 |
| N3 | 获取当前日期 | 无 | 当前日期 `date` | 提供时间判断基准 |
| N4 | 简历内容分块 | 简历全文 | `base_info`、`skill`、`education`、`work_exp`、`project_exp`、`self`、`context` | 把非结构化文本变成结构化字段 |
| N5 | 个人信息评估 | `base_info`、`context`、`date` | 个人信息评估结果 | 检查求职意向、薪资、联系方式、年限 |
| N6 | 技能评估 | `skill`、`context`、`project_exp` | 技能评估结果 | 检查技能和项目是否互证 |
| N7 | 学历信息评估 | `education`、`context`、`date` | 学历评估结果 | 检查学历信息和位置 |
| N8 | 工作经历评估 | `work_exp`、`context`、`date` | 工作经历评估结果 | 检查职责、时间线和项目混写问题 |
| N9 | 项目经历循环 | `project_exp` 数组 | 项目评估结果列表 | 逐个处理多个项目 |
| N9a | 项目经历评估 | 单个项目、`context`、`date`、`forbid_list` | 项目规则评估结果 | 检查结构、技术、职责、成果、违禁词 |
| N9b | 项目 Query 优化 | 单个项目 | 检索 query | 提升模板库检索质量 |
| N9c | 简历模板库检索 | query | 相似模板内容 | 为查重提供参考 |
| N9d | 简历重复度评估 | 项目内容、检索结果 | 重复度评估结果 | 判断是否和模板高度雷同 |
| N9e | 单项目结果整合 | 项目评估、重复度评估 | 单项目综合结论 | 合并单个项目的两类结果 |
| N10 | 个人评价评估 | `self`、`context` | 个人评价评估结果 | 检查是否空泛、是否有事实支撑 |
| N11 | 评估结果整合 | 所有模块结果 | 完整评估报告 | 去重、润色、结构化输出 |
| N12 | 结束 | 完整报告 | Markdown 文本 | 返回最终结果 |

## 三、简历评估模块主流程

### 第 1 步：开始节点

输入：用户上传的简历文件。

输出：简历文件对象或文件 URL。

作用：作为整个简历评估流程的入口。

易错点：

1. 输入类型没有设置成文件。
2. 后续节点拿不到文件 URL。
3. 没有确认 PDF、DOC、图片简历是否都能处理。

### 第 2 步：查询违禁词数据库

输入：无特殊输入，或查询条件为数据存在即可。

输出：违禁词列表。

作用：后续项目经历评估时判断是否出现课程项目原名、雷同项目名或风险词。

为什么用数据库：

1. 违禁词会不断更新。
2. 数据库方便增删改查。
3. 多条工作流可以复用同一份数据。

易错点：

1. 查询字段选多了，导致后续引用复杂。
2. 没有拿到真正需要的输出列表。
3. 把违禁词写死在提示词里，后续维护困难。

### 第 3 步：简历文字提取

输入：开始节点传入的简历文件 URL。

输出：简历全文文本。

作用：把 PDF、Word 或图片简历转换成大模型可以处理的文字。

易错点：

1. 文件类型和插件要求不匹配。
2. OCR 对表格、排版复杂简历识别不准确。
3. 没有检查提取结果，后续评估全基于错误文本。

### 第 4 步：获取当前日期

输入：不需要输入。

输出：当前日期时间。

作用：辅助判断毕业时间、工作年限、项目周期是否合理。

易错点：

1. 认为当前日期不重要。
2. 工作年限判断时只看简历文字，不结合当前时间。

### 第 5 步：内容分块

输入：简历全文。

输出：结构化字段。

建议字段：

| 字段名 | 内容 |
|---|---|
| `name` | 姓名 |
| `base_info` | 基本信息 |
| `skill` | 个人技能 |
| `education` | 教育经历 |
| `work_exp` | 工作经历 |
| `project_exp` | 项目经历数组 |
| `self` | 个人评价 |
| `context` | 简历整体总结 |

作用：把一整份简历拆成后续节点可独立处理的小块。

易错点：

1. `project_exp` 没有设置成数组。
2. 字段名前后不统一，导致后续节点引用失败。
3. 分块提示词太模糊，模型把工作经历和项目经历混在一起。

### 第 6 步：个人信息评估

输入：`base_info`、`context`、当前日期。

输出：个人信息评估结果。

检查重点：

1. 求职意向是否明确。
2. 是否写死期望薪资。
3. 联系方式是否规范。
4. 工作年限是否合理。

易错点：

1. 只评价格式，不评价求职意向。
2. 忽略时间线。

### 第 7 步：技能评估

输入：`skill`、`project_exp`、`context`。

输出：技能评估结果。

检查重点：

1. 技能是否和项目经历对应。
2. 项目中出现的关键技术是否在技能中体现。
3. “熟练”“掌握”的技术是否有项目支撑。

易错点：

1. 只看技能写得多不多，不看是否能证明。
2. 技能和项目脱节。

### 第 8 步：学历评估

输入：`education`、`context`、当前日期。

输出：学历评估结果。

检查重点：

1. 学校、专业、学历、时间是否完整。
2. 学历位置是否适合。
3. 是否需要避短，把项目和工作经历放在更靠前位置。

易错点：

1. 不结合整体简历判断位置。
2. 把学历问题说得过重，忽略求职方向。

### 第 9 步：工作经历评估

输入：`work_exp`、`context`、当前日期。

输出：工作经历评估结果。

检查重点：

1. 工作职责是否清楚。
2. 工作经历和项目经历是否混写。
3. 时间线是否合理。
4. 是否与项目内容冲突。

易错点：

1. 工作经历写成项目详情。
2. 工作时间和项目周期对不上。

### 第 10 步：个人评价评估

输入：`self`、`context`。

输出：个人评价评估结果。

检查重点：

1. 是否空泛。
2. 是否有事实支撑。
3. 是否和岗位方向相关。

易错点：

1. 没有个人评价时强行输出问题。
2. 只说“认真负责”，不给证据。

### 第 11 步：项目经历循环

输入：`project_exp` 数组。

输出：每个项目的评估结果列表。

循环逻辑：

1. 取出第一个项目。
2. 做项目经历评估。
3. 做项目 Query 优化。
4. 检索简历模板知识库。
5. 做项目重复度评估。
6. 整合当前项目结果。
7. 继续处理下一个项目。

为什么需要循环：

项目数量不固定，但每个项目都要执行同样的处理规则。

易错点：

1. 把多个项目混在一个节点里评估。
2. 循环输出没有汇总。
3. 项目查重只看项目名称，不看技术点、职责和成果表达。

### 第 12 步：结果整合

输入：所有模块评估结果。

输出：完整简历评估报告。

报告建议结构：

1. 总体结论。
2. 简历优点。
3. 主要问题。
4. 分模块修改建议。
5. 项目经历重点风险。
6. 综合评价。

易错点：

1. 简单拼接各节点结果，不做去重。
2. 整合节点杜撰前面没有发现的问题。
3. 输出结构混乱，用户不知道应该怎么改。

## 四、学习顺序建议

### 第一轮：先看懂全流程

先看流程，不急着看提示词细节。

目标：知道从简历文件到评估报告，中间到底经过了哪些处理步骤。

### 第二轮：重点看内容分块

观察简历全文如何变成结构化字段。

目标：理解非结构化文本到结构化数据的转换。

### 第三轮：重点看项目循环

观察项目数组如何逐个进入循环体。

目标：理解循环处理不固定数量数据。

### 第四轮：最后看最终报告

对比单模块输出和整合报告。

目标：理解结果整合不是可有可无，而是产品体验的一部分。
