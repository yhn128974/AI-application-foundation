## 一、大模型发展的关键时间节点

### 1. 定义

大模型是指参数规模大、训练数据量大、可以完成理解、生成、推理、总结、分类、信息抽取等任务的人工智能模型。

### 2. 面试防穿帮时间线

学习大模型历史，不是为了背一堆年份，而是为了面试和项目表达时不穿帮。

比如：如果你在讲 2020 年以前的项目，就不能说“当时用 ChatGPT 做了智能客服”，因为 ChatGPT 是 2022 年 11 月才发布的。不同时间点能说的模型和技术要符合当时的技术背景。

| 时间 | 代表模型或技术 | 重点 |
|---|---|---|
| 2012 | AlexNet | 深度学习在图像识别任务中取得重要突破，让 CNN 被更多人重视 |
| 2017 | Transformer | 后续大语言模型的重要基础结构，注意力机制成为核心 |
| 2018 | GPT-1、BERT | GPT 代表生成式预训练方向，BERT 代表理解式预训练方向 |
| 2019 | GPT-2 | 生成能力明显增强，文本生成效果开始受到大量关注 |
| 2020 | GPT-3 | 大参数规模带来更强的少样本学习能力，Prompt 价值开始凸显 |
| 2021 | CLIP、DALL·E | 文本和图像开始更紧密结合，多模态方向受到关注 |
| 2022 | ChatGPT、Stable Diffusion | ChatGPT 推动大模型进入大众视野，文生图工具快速普及 |
| 2023 | GPT-4、Claude、LLaMA、通义千问 Qwen | 高能力闭源模型与开源模型并行发展，国内大模型开始大量落地 |
| 2024 | GPT-4o、Claude 3、Gemini 1.5、Llama 3、Qwen2 | 多模态、长上下文、开源大模型能力快速提升 |
| 2025 | DeepSeek-R1、Qwen3 | 推理模型和高性价比模型受到广泛关注，国产模型影响力进一步增强 |

### 3. 面试表达时怎么用

| 如果你想表达 | 更稳妥的说法 |
|---|---|
| 讲 2017 年前后的技术 | 可以说 Transformer 架构出现，为后续大语言模型打基础 |
| 讲 2018-2020 年 NLP 技术 | 可以说 BERT、GPT 系列推动预训练语言模型发展 |
| 讲 2020 年左右的能力 | 可以说 GPT-3 展示了大规模语言模型的少样本学习能力 |
| 讲 2022 年后的应用 | 可以说 ChatGPT 推动大模型进入大众应用阶段 |
| 讲 2023 年后的项目 | 可以说 GPT-4、Claude、LLaMA、通义千问等模型可用于真实业务探索 |
| 讲 2024 年后的应用 | 可以说多模态、长上下文、开源模型能力明显增强 |
| 讲 2025 年后的趋势 | 可以说推理模型、低成本高性能模型、国产模型影响力明显提升 |

### 4. 面试中不能乱说的点

| 错误说法 | 为什么不严谨 | 正确表达 |
|---|---|---|
| 2020 年用 ChatGPT 做客服 | ChatGPT 2022 年才发布 | 2020 年可以说基于 GPT-3 或传统 NLP 方案探索 |
| 2018 年用 GPT-4 做项目 | GPT-4 2023 年才发布 | 2018 年可以说 BERT、GPT-1 这类预训练模型 |
| 2021 年用 DeepSeek-R1 做推理 | DeepSeek-R1 是 2025 年代表模型 | 2021 年更适合说 GPT-3、CLIP、DALL·E 等方向 |
| 说所有大模型都是 ChatGPT | ChatGPT 是产品，不等于所有大模型 | 应该说大语言模型或生成式 AI 模型 |
| 说 RAG 是 2017 年 Transformer 同期就普及 | RAG 作为企业知识库方案是后续大模型应用中逐渐普及 | 可以说 RAG 是大模型落地中解决知识依据的重要方案 |

### 5. 作用

学习发展节点不是为了背历史，而是为了理解：

1. 大模型不是突然出现的，而是长期技术积累的结果。
2. 大模型能力来自数据、算法、算力共同发展。
3. 今天学习提示词，是为了把现成大模型能力接入实际项目。

### 6. 重点

人工智能发展的三个核心驱动力：

1. 数据：模型学习的材料。
2. 算法：模型学习规律的方法。
3. 算力：支撑大规模训练和推理的硬件能力。

### 7. 难点

不要把“大模型发展史”理解成单纯背年份。它真正要说明的是：现在的大模型应用，是建立在深度学习、Transformer、海量数据和强大算力基础上的。

面试中最重要的是时间顺序不要乱：

```text
AlexNet → Transformer → GPT/BERT → GPT-3 → ChatGPT → GPT-4 → 多模态/开源模型 → 推理模型
```

## 二、大模型幻觉

### 1. 定义

大模型幻觉是指：模型生成了错误、无依据、和事实不一致，或者不符合用户要求的内容。

大白话理解：

> 模型看起来说得很自信，但内容可能是编的，或者没有按要求回答。

### 2. 分类

| 类型 | 定义 | 例子 |
|---|---|---|
| 事实性幻觉 | 模型输出内容和现实事实不一致 | 编造不存在的论文、作者、公司新闻 |
| 忠实性幻觉 | 模型输出内容和用户指令、上下文不一致 | 要求只输出 JSON，模型却输出解释文字 |

### 3. 作用

理解幻觉是为了知道：大模型不能无条件相信。尤其是企业项目里，模型输出可能会进入数据库、报表、客服回复或业务流程，所以必须设计约束和校验。

### 4. 解决方法

| 方法 | 作用 |
|---|---|
| 写清提示词 | 限定角色、任务、格式、边界，减少模型乱答 |
| 提供参考资料 | 让模型基于资料回答，减少凭空生成 |
| 使用 RAG | 先检索知识库，再把资料交给模型回答 |
| 使用工具校验 | 对日期、金额、JSON 格式等内容用程序检查 |
| 人工复核 | 对低置信度或高风险结果交给人工确认 |

### 5. 重点

幻觉最危险的地方不是“看起来假”，而是“看起来很真”。模型可能把不存在的来源、数据、结论说得非常完整。

### 6. 易错点

| 错误理解 | 正确理解 |
|---|---|
| 模型说得自信就一定是真的 | 模型可能一本正经地生成错误内容 |
| 模型出错就是模型完全不能用 | 模型可用，但要加提示词约束、资料依据和程序校验 |
| 幻觉只和事实有关 | 没按用户要求输出，也属于忠实性幻觉 |

## 三、提示词工程

### 1. 定义

提示词工程是通过设计清晰、结构化的指令，引导大模型按照指定角色、任务、步骤、边界和格式完成任务的方法。

### 2. 作用

提示词工程的作用是让模型：

1. 更清楚地理解任务。
2. 更稳定地输出结果。
3. 更少产生幻觉。
4. 更容易被程序继续处理。
5. 更贴近真实业务需求。

### 3. 提示词和用户问题的区别

用户问题只是提示词的一部分。

真实项目中的提示词可能包含：

1. 系统角色。
2. 用户原始问题。
3. 业务背景。
4. 参考资料。
5. 示例输入和输出。
6. 输出格式。
7. 边界规则。
8. 工具调用结果。

### 4. 提示词工程五项原则

| 原则 | 定义 | 作用 | 示例 |
|---|---|---|---|
| 清晰的指令 | 把任务、背景、限制、格式说清楚 | 减少模型误解 | “请输出 JSON，字段为 name、phone、address” |
| 文本参考 | 给模型提供依据资料 | 减少凭空发挥 | “请根据三引号中的资料回答” |
| 复杂任务拆解 | 把大任务拆成多个小步骤 | 降低任务难度 | 先提取问题，再判断情绪，再给建议 |
| 给模型示例 | 提供输入和输出样例 | 让模型模仿格式和风格 | few-shot 示例 |
| 调用外部工具 | 让模型判断工具，程序执行工具 | 让模型不只回答，还能间接做事 | 查天气、查数据库、调用接口 |

### 5. 重点

提示词不是越长越好，而是越清楚越好。好的提示词要让模型知道：

1. 你是谁。
2. 你要做什么。
3. 根据什么做。
4. 按什么步骤做。
5. 不能做什么。
6. 最后输出什么格式。

### 6. 难点

难点在于把“模糊需求”变成“模型能执行、程序能接收”的结构化任务说明。

模糊需求：

```text
帮我分析客户反馈。
```

结构化提示词：

```text
你是一个客户反馈分析助手。

任务：
1. 判断客户情绪，只能是：正面、负面、中性。
2. 提取客户提到的主要问题。
3. 给出一句客服回复建议。

输出格式：
{
  "emotion": "正面|负面|中性",
  "problem": "客户问题",
  "suggestion": "回复建议"
}

客户反馈：
"""
这个 AI 写作工具生成速度挺快，但是经常答非所问，导出的格式也有点乱。
"""
```

## 四、RAG、微调和 Agent

### 1. RAG

#### 定义

RAG 是检索增强生成。它会先从知识库中检索相关资料，再把资料和用户问题一起交给大模型生成答案。

#### 作用

RAG 主要解决：

1. 模型知识过时。
2. 模型不知道企业内部资料。
3. 模型回答没有依据。

#### 类比

RAG 像开卷考试。模型不是只靠自己的记忆回答，而是先查资料，再根据资料作答。

### 2. 微调

#### 定义

微调是在已有模型基础上，用特定领域或任务数据继续训练模型，让模型长期适配某类任务。

#### 作用

微调主要解决：

1. 模型长期风格不统一。
2. 模型需要稳定掌握某类领域表达。
3. 模型需要大量适配同一种任务。

#### 和提示词的区别

提示词是调用时临时给规则；微调是通过训练改变模型后续表现。

### 3. Agent

#### 定义

Agent 是智能体。它让模型不仅能回答问题，还能根据目标拆解任务、选择工具，并由程序执行工具。

#### 作用

Agent 主要解决：

1. 需要多步骤执行的任务。
2. 需要调用外部工具的任务。
3. 需要根据结果继续调整的任务。

#### 例子

用户说：“帮我规划明天去广州的行程。”

Agent 可能需要：

1. 调用定位工具获取出发地。
2. 调用天气工具查询广州天气。
3. 调用搜索工具查景点。
4. 调用交通工具查路线。
5. 整合结果生成计划。

### 4. 对比总结

| 技术 | 解决什么 | 大白话 |
|---|---|---|
| 提示词工程 | 模型怎么答 | 把话说清楚 |
| RAG | 回答依据从哪来 | 开卷考试 |
| 微调 | 模型长期擅长什么 | 回炉深造 |
| Agent | 模型如何调用工具完成任务 | 智能任务管家 |

## 五、大模型提示词中的角色划分

### 1. 定义

在大模型对话接口中，常见角色有：

1. `system`
2. `user`
3. `assistant`
4. `tool`

这些角色共同组成 `messages`，也就是提交给模型的消息列表。

### 2. 三种核心角色

| 角色 | 定义 | 作用 |
|---|---|---|
| `system` | 系统角色 | 设定模型身份、任务规则、输出边界 |
| `user` | 用户角色 | 提出具体问题或提供待处理数据 |
| `assistant` | 助手角色 | 表示模型历史回复，也可以作为示例答案 |

### 3. tool 角色

`tool` 通常用于 Agent 或工具调用场景，表示外部工具执行后的结果。

例如：

1. 天气接口返回的天气信息。
2. 数据库查询结果。
3. 搜索引擎返回的网页摘要。

### 4. 重点

一句话记忆：

> `system` 定规则，`user` 给任务，`assistant` 给回答，`tool` 给工具结果。

### 5. 难点

难点是理解 `assistant` 的两种用法：

1. 在普通 API 调用中，`assistant` 是模型实时生成的回复。
2. 在 few-shot 示例中，`assistant` 可以作为提前写好的标准答案，让模型模仿。

## 六、调用云端大模型的方法

### 1. 定义

调用云端大模型，就是通过 Python 代码请求模型服务，把问题发送给模型，再接收模型返回结果。

### 2. 调用云端模型的基本步骤

1. 安装 SDK，例如 `openai` 或 `dashscope`。
2. 获取并配置 API Key。
3. 创建客户端对象或设置密钥。
4. 准备 `messages`。
5. 调用模型。
6. 取出模型返回内容。

### 3. API Key

API Key 是调用模型服务的密钥。

正确做法：

1. 不要写进公开代码。
2. 不要截图发群。
3. 推荐放到环境变量中。
4. 首次配置环境变量后，重启 PyCharm。

### 4. OpenAI 兼容方式代码

```python
"""
需求：
    使用 OpenAI 兼容方式调用阿里百炼模型。

步骤：
    1. 从环境变量读取 API Key，避免密钥泄露。
    2. 创建 OpenAI 客户端对象。
    3. 准备 messages，包含 system 和 user。
    4. 调用模型并打印模型生成的文本内容。
"""

import os  # 用于读取环境变量，避免把真实 API Key 写进代码
from openai import OpenAI  # OpenAI 客户端类，用于发送模型调用请求


api_key = os.getenv("OPENAI_API_KEY")  # 从环境变量中读取密钥

if not api_key:
    # 如果没有读到密钥，说明环境变量没有配置好，或者配置后没有重启 PyCharm
    raise ValueError("没有读取到 OPENAI_API_KEY，请检查环境变量并重启 PyCharm。")

client = OpenAI(
    api_key=api_key,  # 用于证明调用者身份
    base_url="https://dashscope.aliyuncs.com/compatible-mode/v1",  # 阿里百炼 OpenAI 兼容接口地址
)

completion = client.chat.completions.create(
    model="qwen-plus",  # 指定要调用的模型名称
    messages=[
        {
            "role": "system",
            "content": "你是一个简洁的 AI 助手，请用中文回答。"
        },
        {
            "role": "user",
            "content": "请用一句话解释提示词工程。"
        },
    ],
)

# choices 表示候选回复列表，通常取第 1 个
# message 表示模型返回的消息对象
# content 才是真正要打印给用户看的文本内容
print(completion.choices[0].message.content)
```

### 5. DashScope 原生方式代码

```python
"""
需求：
    使用 DashScope 原生 SDK 调用阿里通义模型。

步骤：
    1. 导入 dashscope。
    2. 从环境变量读取 DASHSCOPE_API_KEY。
    3. 使用 dashscope.Generation.call 调用模型。
    4. 从 response.output["text"] 中取出模型回复。
"""

import os  # 用于读取环境变量
import dashscope  # 阿里百炼官方 SDK


dashscope.api_key = os.getenv("DASHSCOPE_API_KEY")  # 设置 DashScope 调用密钥

if not dashscope.api_key:
    raise ValueError("没有读取到 DASHSCOPE_API_KEY，请检查环境变量并重启 PyCharm。")

response = dashscope.Generation.call(
    model="qwen-plus",  # 指定模型名称
    messages=[
        {
            "role": "system",
            "content": "你是一个简洁的 AI 助手，请用中文回答。"
        },
        {
            "role": "user",
            "content": "请用一句话解释 RAG。"
        },
    ],
)

# DashScope 原生方式的文本结果通常在 output["text"] 中
print(response.output["text"])
```

### 6. OpenAI 风格返回结构

OpenAI 风格调用返回的不是普通字符串，而是一个结构化对象。

最常用的取值路径：

```python
completion.choices[0].message.content
```

含义：

1. `choices`：模型返回的候选结果列表。
2. `choices[0]`：取第一个候选结果。
3. `message`：候选结果中的消息对象。
4. `content`：模型真正生成的文本。

另外，返回值中的 `usage` 通常表示 Token 消耗，后续做成本统计时会用到。

## 七、调用外部工具

### 1. 定义

调用外部工具是指：模型判断当前任务需要什么工具，程序负责真正执行工具，并把工具结果交给模型继续生成答案。

### 2. 作用

外部工具可以弥补大模型本身不能直接完成的动作，例如：

1. 查天气。
2. 查数据库。
3. 搜索网页。
4. 执行计算。
5. 调用业务系统接口。

### 3. 重点

模型本身不是浏览器、数据库或计算器。真正执行动作的是程序，模型负责理解任务和决定工具使用方向。

### 4. 简单流程

```text
用户提出目标
→ 模型判断需要调用工具
→ 程序执行工具
→ 工具返回结果
→ 模型基于结果生成最终回答
```

### 2. 今日难点

1. 分清提示词和用户问题的区别。
2. 分清事实性幻觉和忠实性幻觉。
3. 分清提示词、RAG、微调、Agent 各自解决的问题。
4. 理解 `assistant` 既可以表示模型回复，也可以作为 few-shot 示例答案。
5. 理解模型返回值中为什么要取 `choices[0].message.content`。

## 九、今日易错点

| 易错点 | 错误 | 正确 |
|---|---|---|
| 提示词 | 提示词就是用户随便问一句 | 提示词是一整套任务说明 |
| 幻觉 | 模型说得自信就是真的 | 模型可能生成无依据内容 |
| RAG | RAG 是重新训练模型 | RAG 是检索资料后增强回答 |
| 微调 | 微调就是改提示词 | 微调是继续训练模型 |
| Agent | Agent 只是聊天机器人 | Agent 能拆任务并调用工具 |
| API Key | 可以写进代码里 | 应放环境变量中 |
| 返回值 | completion 是最终文本 | `completion.choices[0].message.content` 才是常用文本内容 |
