## 二、今日课程主线

前一天的简历评估模块解决的是“看简历、找问题”。今天要继续把 AI 面试助手做完整，让系统不仅能看简历，还能分析面试录音、根据简历生成面试题，并通过一个统一的智能体入口把这些能力串起来。

今天可以用一句话概括：

把“单个工作流功能”升级成“完整 AI 面试助手产品”。

整体链路如下：

1. 简历评估：上传简历，发现简历问题。
2. 录音分析：上传面试录音，分析面试表现。
3. 面试题生成：上传简历，生成针对性的模拟面试题。
4. Agent 编排：用户不用记住三个工作流，只需要和一个智能体对话。
5. 批处理：大量简历或录音不再一个个手动点，而是通过 API 和程序批量处理。

## 三、录音分析模块

### 1. 录音分析模块解决什么问题

面试结束后，很多人只知道“自己好像答得不好”，但不知道具体是哪一道题没答好，也不知道标准回答应该怎么组织。

录音分析模块要解决的问题是：

1. 把面试录音转成文字。
2. 分清哪些话是面试官说的，哪些话是应试者说的。
3. 提取自我介绍和每一组问答。
4. 对自我介绍进行评价。
5. 对每一道技术问题的回答进行评价。
6. 汇总成一份可读的面试复盘报告。

它的核心价值是：把一次模糊的面试经历变成可以复盘、可以修改、可以训练的数据。

### 2. 录音分析的完整流程

录音分析模块的流程可以拆成五步：

1. 输入面试语音：用户上传 MP3 或 WAV 格式录音。
2. 面试语音转文字：通过 ASR 插件把声音转成文本。
3. 角色划分与概要提取：识别面试官、应试者、自我介绍和问答对。
4. 面试表现评估：评估自我介绍和每一道面试回答。
5. 报告内容生成：把整体描述、问题评价、改进建议整合成报告。

### 3. ASR 是什么

ASR 的英文全称是 Automatic Speech Recognition，中文叫自动语音识别。

它解决的问题是：把声音转成文字。

常见例子：

1. 微信语音转文字。
2. 会议实时字幕。
3. 手机语音输入。
4. 面试录音转写。

在本项目中，ASR 的作用是把面试录音转成可被大模型继续处理的文本。

### 4. TTS 是什么

TTS 的英文全称是 Text To Speech，中文叫文本转语音。

它解决的问题是：把文字读成声音。

本节课主要使用 ASR，不重点使用 TTS。TTS 可以理解为 ASR 的反方向，以后如果要做“AI 面试官开口提问”，就会用到 TTS。

### 5. ASR 和说话人识别的区别

ASR 负责判断“说了什么”。

说话人识别负责判断“是谁说的”。

这两个问题不是一回事：

| 能力 | 解决的问题 | 输出 |
|---|---|---|
| ASR | 这段声音说了什么内容 | 一段文字 |
| 说话人识别 | 这句话是谁说的 | 说话人 A、B、C |
| 语义分角色 | 根据上下文判断谁是面试官、谁是应试者 | 面试官/应试者对话 |

在本项目里，Coze 中的语音识别插件先完成 ASR，再用大模型根据语义进行角色划分。

### 6. 为什么这里用语义分角色

真实会议场景可能需要声纹识别、时间戳对齐和说话人聚类，但面试场景通常只有两个角色：面试官和应试者。

面试对话有明显语义特征：

1. 面试官经常提出问题。
2. 应试者经常回答问题。
3. “请介绍一下你自己”通常来自面试官。
4. “我毕业于……”通常来自应试者。

所以在这个固定场景下，使用大模型根据语义划分角色，成本更低，搭建更简单，也更适合 Coze 工作流演示。

### 7. 角色划分节点的作用

角色划分节点接收 ASR 转写后的文本，输出带角色标记的对话原文。

正确效果示例：

```text
面试官：请你介绍一下自己的项目经历。
应试者：我主要做过一个基于 RAG 的知识库问答项目……
面试官：这个项目里向量检索是怎么做的？
应试者：我们先对文档进行切分，然后生成向量……
```

易错点：

1. 不要把所有内容都当成应试者发言。
2. 不要丢掉原文中的卡顿、停顿和明显异常。
3. 如果不是面试录音，不应该强行分析。

### 8. 概要提取节点的作用

概要提取节点主要输出两个结果：

1. `self_introduce`：自我介绍原文。
2. `summarize`：面试整体概要。

注意：如果面试官中途问“介绍一下你的项目”，这不属于开场自我介绍，而属于问答环节。

### 9. 问答对提取节点的作用

问答对提取节点把整场面试拆成多个“问题 + 回答”。

这样做的原因是：后续评估不能只对整段录音笼统打分，而应该逐题评估。

例如：

```text
问题：RAG 的基本流程是什么？
回答：先把文档切分，然后做向量化，再检索相关内容，最后交给大模型生成答案。
```

易错点：

1. 不要把自我介绍当成普通问答。
2. 追问类问题要补全上下文，例如“解码器呢”要改写成“Transformer 的解码器是什么”。
3. 输出用字符串数组更稳定，不要一开始就追求复杂对象结构。

## 四、面试表现评估

### 1. 自我介绍评估

自我介绍评估关注的是开场表达是否完整、清楚、有重点。

常见评价维度：

1. 是否包含姓名、学历、工作经历、项目经历。
2. 是否突出自己做过什么，而不是只说空泛优点。
3. 是否技能罗列过多。
4. 项目介绍是否时间过长。
5. 是否用事实支撑能力。

错误示例：

```text
我学习能力强，沟通能力好，抗压能力强，熟悉 Python、MySQL、Redis、Linux、深度学习、NLP、RAG、Agent……
```

问题：软素质太多，技能堆砌太多，没有证明能力的事实。

正确方向：

```text
我主要参与过一个企业知识库问答项目，负责文档清洗、向量检索和召回效果优化。项目中我把文档按照标题层级切分，并对召回结果做了重排，使答案引用更加稳定。
```

优点：有项目、有职责、有动作、有结果。

### 2. 面试回答评估为什么要用循环

一场面试会有很多道题，题目数量不固定。

如果不用循环，就很难稳定地逐题处理。

循环结构解决的问题是：

1. 有几道题就处理几次。
2. 每道题都走同样的评估标准。
3. 每道题都可以独立检索知识库。
4. 每道题都可以单独入库。
5. 最后把所有评估结果汇总。

### 3. RAG 在面试回答评估中的作用

RAG 的作用是给模型提供参考答案。

如果只让大模型凭记忆判断学生回答对不对，容易出现不稳定。加入题库和面试宝典后，模型可以先查参考资料，再做判断。

本项目中的评估逻辑：

1. 用问题去面试题知识库检索。
2. 如果查到相关答案，就基于知识库判断。
3. 如果查不到，使用互联网搜索兜底。
4. 根据标准答案和用户回答进行比较。
5. 输出 A/B/C/D 等级和改进建议。

### 4. 为什么要把面试题入库

面试题入库不是为了当前这一道题，而是为了以后。

今天从录音中提取到的问题，存进数据库后，后续生成面试题、分析其他录音时都可以复用。

这就是项目中的数据积累：

1. 用户使用越多。
2. 系统收集到的问题越多。
3. 题库越丰富。
4. 后续生成和评估效果越好。

这个思路在真实 AI 产品中很常见，叫做数据飞轮。

## 五、面试题生成模块

### 1. 面试题生成模块解决什么问题

简历评估告诉你简历哪里有问题，录音分析告诉你上一次面试哪里答得不好。

面试题生成模块则解决“下一次应该练什么”的问题。

它的输入是简历文件，输出是一组模拟面试题。

### 2. 面试题生成流程

面试题生成模块的流程：

1. 解析简历文件。
2. 提取技能点和项目经历。
3. 查询最近 100 道真实面试题。
4. 基于技能点生成技术问题。
5. 基于项目经历生成项目追问。
6. 整合、去重、补充人事问题。
7. 输出面试题集合。

### 3. 为什么要拆细技能点

简历里常见技能描述是一个长句：

```text
熟悉深度学习原理，对 RNN、LSTM、Transformer 的原理有深入研究，熟练使用 PyTorch 搭建神经网络。
```

这句话包含多个技术点：

1. 深度学习原理。
2. RNN。
3. LSTM。
4. Transformer。
5. PyTorch。
6. 神经网络搭建。

如果不拆细，模型很难生成精准问题。拆细后，可以针对每个技术点单独生成问题。

### 4. 技能题和项目题的区别

技能题偏通用，可以结合面试宝典、真实题库和联网搜索。

项目题偏个性化，需要根据简历项目内容生成。

| 类型 | 来源 | 生成方式 |
|---|---|---|
| 技能题 | 技能点、题库、面试宝典 | 检索 + 生成 |
| 项目题 | 简历项目经历 | 基于项目内容直接追问 |
| 人事题 | 常见面试场景 | 作为补充题加入 |

### 5. 面试题整合节点的作用

面试题整合节点不是简单拼接，而是要做整理：

1. 去掉重复题。
2. 保留和岗位最相关的题。
3. 去除口语化表达。
4. 控制不同技术点的题目数量。
5. 补充适当的人事问题。

## 六、智能体编排

### 1. 为什么需要智能体编排

前面我们已经有多个工作流：

1. 简历评估工作流。
2. 录音分析工作流。
3. 面试题生成工作流。

如果让用户自己选择工作流，会增加使用成本。

智能体编排的作用是：让用户只面对一个入口，由 Agent 根据用户输入判断应该调用哪个工作流。

### 2. 单 Agent 和 Multi-Agent

本项目场景不算复杂，用户意图比较容易判断，所以可以使用单 Agent 的自助规划模式来管理多个工作流。

可以把三个工作流理解成三条流水线：

1. 简历评估流水线。
2. 录音分析流水线。
3. 面试题生成流水线。

Agent 负责判断用户要走哪条流水线。

### 3. Agent 的核心提示词要解决什么

Agent 提示词不是单纯写人设，而是要写清楚：

1. 角色是什么。
2. 能做哪些事。
3. 什么情况下调用哪个工作流。
4. 处理不了的情况怎么回复。
5. 是否对用户隐藏内部调用细节。

例如：

1. 用户上传简历并说“帮我看看简历”，调用简历评估。
2. 用户上传录音文件，调用录音分析。
3. 用户上传简历并说“帮我生成面试题”，调用面试题生成。
4. 用户闲聊或问无关问题，固定提示当前只支持项目相关能力。

## 七、批处理和 API 调用

### 1. 为什么需要批处理

在课堂演示中，我们可以手动上传一个文件，点击一次运行。

真实工作中，如果有 100 份简历、50 段录音，一个个手动上传就不现实了。

批处理解决的问题是：

1. 自动遍历文件夹。
2. 自动上传文件。
3. 自动调用智能体。
4. 自动保存结果。
5. 自动统计成功和失败。

### 2. API 调用的意义

发布 API 后，Coze 不再只是网页上的工具，而可以被 Python 程序、后台服务、企业系统调用。

这一步意味着：

1. 从“手动工具”变成“可集成服务”。
2. 从“单次处理”变成“批量处理”。
3. 从“课堂项目”接近“真实业务系统”。

### 3. 批处理的基本思路

批处理不需要一开始写得很复杂，基本流程是：

1. 准备一个文件夹，里面放简历或录音。
2. 遍历文件夹中的文件。
3. 判断文件格式是否符合要求。
4. 上传文件到 Coze。
5. 构造用户消息。
6. 调用 Agent。
7. 接收输出结果。
8. 保存为 Markdown 文件。

## 八、今日易错点

| 易错点 | 错误做法 | 正确做法 |
|---|---|---|
| 音频格式 | 上传 m4a 后直接分析 | 使用 MP3 或 WAV |
| ASR 超时 | 使用默认超时时间 | 长录音把超时调到 600 秒 |
| ASR 和说话人识别 | 以为 ASR 会自动分清谁说话 | ASR 只转文字，角色划分要单独处理 |
| 角色划分 | 用弱模型或提示词太短 | 用更强模型，并写清楚面试官/应试者格式 |
| 问答提取 | 不补全追问上下文 | 把“解码器呢”改写成完整问题 |
| 循环处理 | 整段面试一次性评价 | 对问答数组逐题循环评估 |
| 知识库匹配 | 匹配度设置太低 | 提高匹配度，避免错误参考 |
| 面试题生成 | 直接按整段技能生成题 | 先拆细技能点，再生成问题 |
| Agent 编排 | 只写人设，不写调用规则 | 明确什么输入调用什么工作流 |
| 批处理 | 只考虑成功情况 | 要考虑文件不存在、格式错误、调用失败 |

## 九、今日总结

今天的重点不是单独学某一个节点，而是理解完整 AI 项目如何从多个工作流组合成一个产品。

录音分析体现的是“语音到结构化评估”的能力。

面试题生成体现的是“根据用户材料生成个性化训练内容”的能力。

Agent 编排体现的是“把多个功能统一成一个入口”的产品能力。

批处理和 API 调用体现的是“把网页工具接入真实业务系统”的工程能力。

学完今天，应该能说清楚：

1. 录音分析为什么要先 ASR，再角色划分，再逐题评估。
2. 面试题生成为什么要拆技能点和项目经历。
3. Agent 为什么要负责选择工作流。
4. API 和批处理为什么让项目更接近真实工作。
