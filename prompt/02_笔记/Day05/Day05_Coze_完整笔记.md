## 一、今日课程总览

Day04 我们已经学习了智能体、工作流、节点和插件。Day05 要往前走一步：让智能体访问自己的资料、读写自己的业务数据，并处理文本以外的图片、音频、视频。

今天可以分成两条主线：

1. 私有数据访问：让智能体不只依赖模型记忆，而是能使用我们提供的文档和业务数据。
2. 多模态处理：让智能体不只处理文字，也能处理图片、音频、视频，并能生成图片、语音、视频。

用工作场景来理解：

1. 如果你做一个“课程问答助手”，它需要读取课程讲义、PPT、讲课笔记，这更适合知识库。
2. 如果你做一个“学生签到助手”，它需要记录谁签到了、谁没签到，这更适合数据库。
3. 如果你做一个“面试录音分析助手”，它需要把音频转成文字，这就需要 ASR。
4. 如果你做一个“广告生成助手”，它可能需要文案、商品图、配音、视频，这就是多模态 AIGC。

## 二、知识库和数据库的区别

知识库和数据库都属于“私有数据访问”，但它们解决的问题不一样。

知识库更像一个支持快速检索的资料文件夹，适合存放文档、说明书、课程资料、PDF、Word 等内容。它通常用于“读资料、查资料、根据资料回答问题”。

数据库更像一张可以被程序操作的表格，适合存放结构化数据，例如学生信息、订单记录、绩效数据、签到状态、面试题记录。它通常用于“增删改查”。

对比表：

| 对比点 | 知识库 | 数据库 |
|---|---|---|
| 数据形态 | 文档、段落、文本片段 | 表格、字段、记录 |
| 典型来源 | PDF、Word、网页、说明书 | Excel、CSV、业务系统 |
| 核心能力 | 检索和召回相关内容 | 增删改查结构化数据 |
| 是否常修改 | 通常不频繁修改 | 经常新增、修改、删除 |
| 适合场景 | 课程问答、制度问答、产品说明问答 | 签到、绩效、订单、用户信息 |
| 工作流常见节点 | 知识库检索节点 | 数据库节点 |

正确理解：

1. 知识库适合“从资料里找答案”。
2. 数据库适合“对表格数据做操作”。

错误理解：

1. 只要是自己的数据都放知识库。
2. 只要是文本内容都放数据库。
3. 知识库和数据库可以完全互相替代。

## 三、RAG：为什么要外挂知识库

RAG 是 Retrieval-Augmented Generation 的缩写，通常翻译为“检索增强生成”。它的核心思想是：先从资料中检索相关内容，再把检索到的内容交给大模型生成答案。

大模型本身有几个问题：

1. 知识可能过时。
2. 不知道公司内部资料。
3. 容易在不确定时编造。
4. 微调成本较高，不适合每次资料变化都重新训练模型。

RAG 的思路不是把所有知识都塞进模型，而是把资料放到知识库里，用户提问时先检索，再回答。

标准流程：

```text
原始文档 -> 解析文档 -> 文档分段 -> 向量化 -> 存储到向量数据库 -> 用户提问 -> 检索相关片段 -> 大模型生成答案
```

重点不是“上传文档”四个字，而是理解为什么要分段、为什么要检索、为什么最后还要大模型润色。

## 四、创建知识库的关键步骤

在 Coze 中创建知识库大致包含以下步骤：

1. 进入资源库。
2. 新建知识库资源。
3. 选择知识库类型。
4. 上传文档资料。
5. 选择解析方式。
6. 配置分段策略。
7. 预览分段效果。
8. 保存并在工作流中使用知识库检索节点。

### 1. 文档解析

文档解析就是把 PDF、Word 等文件中的内容读取出来，转换成平台可以处理的文本。

常见问题：

1. PDF 可能是扫描件，需要 OCR。
2. 文档中表格、图片、标题结构可能解析不完整。
3. 文件过大时，解析和后续检索可能更慢。

### 2. 分段

分段就是把一整篇文档切成一个个小片段，也叫 chunk。

为什么要分段？

如果把整本文档当作一个整体，用户问一个小问题时，系统很难精准找到相关位置。分段之后，检索系统可以更准确地找出和问题相关的几个片段。

常见分段策略：

1. 自动分段：平台根据内容自动切分，适合入门。
2. 自定义分段：按符号、标题、字符数等规则切分，适合有明确结构的资料。
3. 层级分段：保留标题层级，适合课程讲义、说明书、制度文档。

分段太大和太小都有问题：

1. 分段太大：召回内容不精准，模型容易读到很多无关内容。
2. 分段太小：上下文不完整，模型可能看不到前因后果。

### 3. 分段重叠

分段重叠是指相邻片段之间保留一部分重复内容。它的作用是避免一句话或一个知识点刚好被切断，导致检索到的片段语义不完整。

例如一段解释 Transformer 的文字，前半句在第一个片段，后半句在第二个片段。如果没有重叠，检索到其中一个片段时，模型可能看不完整。适当重叠可以保证语义连续。

## 五、知识库检索节点核心参数

知识库创建好之后，要在工作流中通过知识库检索节点使用。

常见流程：

```text
开始节点接收用户问题 -> 知识库检索节点检索相关片段 -> 大模型润色整理 -> 结束节点输出答案
```

### 1. 检索策略

常见检索策略包括全文检索、语义检索、混合检索。

全文检索更像关键词匹配。用户问的问题中出现了某个词，系统就去文档中找这个词。优点是直接，缺点是表达换一种说法就可能找不到。

语义检索更像理解意思。它会把问题和文档片段转成向量，然后计算相似度。即使用户没有说完全一样的关键词，只要意思接近，也有机会召回。

混合检索把全文检索和语义检索结合起来，通常更稳。对于课程资料、业务制度、产品说明这类文档，混合检索往往更适合。

### 2. 向量和相似度

语义检索背后常用向量表示。可以简单理解为：系统把一段话转成一组数字，这组数字代表它的语义位置。

两个句子意思越接近，它们在向量空间中的距离越近。系统会计算相似度，找到最相关的片段。

课堂上不用让学生掌握数学公式，但要让学生理解：语义检索不是靠字面完全一样，而是靠意思相近。

### 3. 最大召回数量

最大召回数量表示一次最多返回几个相关片段。

数量太少，可能漏掉重要信息。

数量太多，模型会读到很多无关内容，回答反而变乱，还会增加成本和耗时。

入门建议先使用默认值，例如 5 个片段，再根据效果调整。

### 4. 最小匹配度

最小匹配度是召回门槛。只有相似度超过这个门槛的片段才会被返回。

匹配度太低，容易召回无关内容。

匹配度太高，可能什么都召不回来。

可以这样理解：

1. 0.5：比较宽松，容易有结果，但可能混入无关内容。
2. 0.7：相对平衡，适合多数入门场景。
3. 0.85：比较严格，适合资料质量高、问题明确的场景。
4. 0.99：非常严格，通常容易召回不到。

### 5. 查询改写

查询改写就是把用户的自然问题改写成更适合检索的问题。

例如用户问：

```text
我昨天看到那个关于模型发展的资料，BERT 和 GPT 到底差在哪？
```

系统可以改写成：

```text
BERT 和 GPT 的区别是什么？
```

改写后的问题更短、更清晰，更适合检索。

### 6. 结果重排

结果重排是在召回多个片段之后，再根据相关性重新排序，把最有价值的内容放到前面。它的作用是提升大模型看到关键信息的概率。

## 六、为什么知识库检索后还要润色

知识库检索节点返回的通常是原始片段。原始片段对系统有用，但对用户不一定友好。

直接返回原始片段的问题：

1. 内容可能零散。
2. 格式不自然。
3. 用户看不出重点。
4. 没有结合用户问题组织答案。

因此要增加一个大模型润色节点。

更稳的设计是：

```text
用户问题 -> 知识库检索
       -> 如果知识库有结果：以知识库为主回答
       -> 如果知识库无结果：调用联网搜索兜底
       -> 大模型融合和润色
       -> 输出答案
```

这个流程的核心不是“美化语言”，而是让系统既有私有资料的准确性，又有联网搜索的兜底能力。

## 七、Coze 数据库：从只读资料到可操作数据

知识库主要用于检索文档，数据库则用于管理结构化数据。

课堂案例中可以创建一个绩效数据表，例如：

| 字段 | 含义 | 类型建议 |
|---|---|---|
| work_code | 工号 | 字符串 |
| name | 姓名 | 字符串 |
| performance_level | 绩效等级 | 字符串 |

注意：工号虽然看起来是数字，但通常不参与计算，更适合存成字符串。否则前导 0、格式统一等问题可能出错。

Coze 数据库创建时要注意：

1. 字段名要和导入 Excel 的表头匹配。
2. 测试数据和线上数据要区分。
3. 权限设置要结合业务理解。
4. 平台会自动添加一些系统字段，例如 ID、UUID、创建时间等。

## 八、数据库查询流程

数据库查询不是直接把用户一句话丢给数据库，而是先从用户话里提取查询条件。

典型流程：

```text
用户输入 -> 意图识别 -> 人名抽取 -> 数据库查询 -> 大模型润色 -> 输出
```

例如用户问：

```text
帮我查一下张三的绩效
```

系统需要先抽取出 `张三`，再去数据库里查 `name == 张三` 的记录。

为什么要润色？

数据库节点返回的可能是 JSON 或表格结构，用户不一定看得懂。最终输出应该变成自然语言，例如：

```text
查询到张三的工号为 1001，当前绩效等级为 B。
```

## 九、数据库新增、更新、删除

### 1. 新增数据

新增数据的核心流程：

```text
用户输入 -> 信息抽取 -> 新增数据节点 -> 输出新增结果
```

例如用户输入：

```text
新增员工乔峰，工号 666，绩效 S。
```

系统需要抽取：

1. 姓名：乔峰
2. 工号：666
3. 绩效：S

再把这些字段写入数据库。

易错点：

1. 抽取字段名和数据库字段名对应不上。
2. 用户少说一个字段，系统仍然直接新增。
3. 新增后没有提示是否成功。

### 2. 更新数据

更新数据相当于 SQL 中的 `WHERE + SET`。

要更新一条记录，必须先定位是哪条记录，再说明要改什么。

例如：

```text
把乔峰工号 666 的绩效改成 D。
```

定位条件：

1. 姓名 = 乔峰
2. 工号 = 666

更新字段：

1. 绩效 = D

为什么常用姓名和工号两个条件？

因为单独用姓名可能重名，单独用工号如果用户输错也危险。联合条件更稳。

### 3. 删除数据

删除数据只需要删除条件，不需要设置更新字段。

例如：

```text
删除乔峰工号 666 的绩效记录。
```

删除条件：

1. 姓名 = 乔峰
2. 工号 = 666

删除操作要谨慎。真实业务中，删除前最好做确认，或者用“软删除”字段标记，不要直接物理删除。

课堂入门阶段可以先掌握节点配置，但要给学生讲清楚真实工作中的风险意识。

## 十、多模态是什么

多模态指 AI 能处理不止一种数据类型。文本是一种模态，图片、音频、视频也是模态。

常见模态：

1. 文本：文章、问题、提示词、报告。
2. 图片：商品图、截图、海报、证件照。
3. 音频：录音、配音、语音消息。
4. 视频：宣传片、教学视频、产品展示。

多模态能力的意义是：让 AI 从“只会读文字”变成“能看、能听、能说、能生成内容”。

## 十一、图像类能力

### 1. 文生图

文生图就是根据文字提示词生成图片。

典型流程：

```text
开始节点接收提示词 -> 图像生成插件 -> 输出图片链接或图片结果
```

应用场景：

1. 电商商品图。
2. 小红书配图。
3. 课程封面图。
4. 广告创意图。
5. 原型视觉探索。

提示词要尽量包含：

1. 主体是什么。
2. 场景在哪里。
3. 风格是什么。
4. 光线、构图、颜色等要求。
5. 不希望出现什么。

### 2. 图片清晰度提升

图片清晰度提升用于改善低分辨率或模糊图片。

流程：

```text
上传图片 -> 图片清晰度提升插件 -> 输出增强后的图片
```

注意：

1. 输入类型要从文本改成图片。
2. 图片要上传完成后再运行。
3. 提升清晰度不是魔法，如果原图信息严重缺失，效果仍然有限。
4. 这类插件通常消耗积分，要注意成本。

## 十二、音频类能力

### 1. ASR：语音识别

ASR 是 Automatic Speech Recognition，意思是语音转文字。

流程：

```text
上传音频 -> 语音识别插件 -> 输出转写文本 -> 大模型润色或分析
```

应用场景：

1. 面试录音转写。
2. 会议纪要。
3. 课堂录音整理。
4. 客服通话分析。

注意：

1. 输入类型要改成音频。
2. 长音频可能需要更长超时时间。
3. ASR 输出可能没有标点，需要后接大模型润色。
4. 识别质量受噪音、口音、多人说话影响。

### 2. TTS：语音合成

TTS 是 Text-to-Speech，意思是文字转语音。

流程：

```text
输入文本 -> 语音合成插件 -> 输出音频链接
```

应用场景：

1. 广告配音。
2. 课程旁白。
3. 智能客服语音回复。
4. 短视频解说。

常见参数：

1. 文本内容。
2. 音色。
3. 语速。
4. 情绪。
5. 语言。

注意：很多 TTS 插件对文本长度有限制，使用前要看插件说明。

## 十三、视频生成能力

视频生成是多模态中成本较高、效果波动也较大的能力。它可以根据文字或图片生成视频。

常见参数：

1. 模型。
2. 分辨率。
3. 时长。
4. 种子值。
5. 提示词。

视频生成的难点：

1. 成本高，Token 或积分消耗大。
2. 人手、肢体、物理运动容易出错。
3. 复杂动作容易“一眼假”。
4. 生成时间较长。

课堂上要让学生掌握基本流程，但也要知道它不是万能的。真实工作中常用策略是：先用大模型优化提示词，再分段生成，再人工挑选和剪辑。

## 十四、和 AI 面试助手项目的关系

今天的内容可以自然连接到 AI 面试助手项目。

项目中的几个模块对应今天的能力：

1. 简历评估：文档提取 + 数据库违禁词 + 大模型分块评估。
2. 面试录音分析：ASR 语音识别 + 大模型角色划分 + 问答对提取 + 结果评估。
3. 面试题生成：简历解析 + 数据库读取历史面试题 + 大模型生成题目。
4. 批处理：循环结构或批量处理能力，处理多个学生、多份简历、多段录音。

这就是今天学习的价值：不是学一个孤立按钮，而是把知识库、数据库、多模态都放到真实 AI 应用里。

## 十五、今日易错点

1. 知识库不是数据库。知识库适合文档检索，数据库适合结构化增删改查。
2. 文档上传后必须关注分段效果，分段不好会影响检索质量。
3. 检索结果不要直接丢给用户，通常需要大模型润色。
4. 知识库无结果时要有兜底方案，例如联网搜索或提示用户资料不足。
5. 数据库字段名、抽取字段名、节点绑定字段要一致。
6. 更新和删除必须有明确条件，不能只靠姓名这种不稳定条件。
7. 工号看起来是数字，但业务上通常是字符串。
8. 多模态节点的输入类型要改对，图片用 image，音频用 audio，文档用 doc 或 file。
9. ASR 输出可能没有标点，需要后续整理。
10. 视频生成成本高、效果不稳定，要让学生理解边界，不要过度承诺。
