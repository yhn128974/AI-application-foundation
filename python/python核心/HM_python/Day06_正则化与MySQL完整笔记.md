### 二. 正则表达式概述

#### 1. [掌握]正则表达式的作用

* **正则表达式**：用一套规则去匹配一类字符串。
* **普通字符串查找**：适合查固定内容，例如查找 `"Python"`。
* **正则表达式查找**：适合查有规律的一类内容，例如手机号、邮箱、日期、订单号、图片地址。

#### 2. [理解]为什么要学习正则表达式

* 在实际开发和数据分析中，经常需要从一大段文本中提取符合规则的数据。
* 在 RAG 文档清洗中，也经常要删除页码、页眉页脚、重复空行、内部标记等噪声。
* 正则表达式不是 Python 独有的，很多编程语言和工具都支持正则表达式。

#### 3. [互动提问]

* **问题 1**：如果只是判断一句话中有没有固定词 `"Python"`，必须用正则吗？
  * **答案**：不必须。普通字符串方法如 `in`、`find()` 就可以完成。
* **问题 2**：如果要从一段文本中提取所有手机号，适合用正则吗？
  * **答案**：适合。手机号是一类有规律的字符串，正则可以按规则批量提取。
* **问题 3**：正则表达式的核心作用是什么？
  * **答案**：用规则匹配、提取、校验或清洗一类字符串。

### 三. re 模块基础

#### 1. [掌握]re 模块使用三步

```python
# 第一步：导入 Python 内置的 re 模块。
# re 模块专门用于正则表达式匹配、提取、替换等操作。
import re

# 第二步：准备一段要处理的文本。
# 这段文本里包含一个手机号。
text = "手机号: 13800138000"

# 第三步：使用正则规则提取手机号。
# r"\d{11}" 表示连续 11 位数字。
# r"" 是原始字符串，能避免反斜杠被 Python 提前转义。
# findall 会找出所有符合规则的内容，并返回列表。
result = re.findall(r"\d{11}", text)

# 打印结果。
# 预期输出：['13800138000']
print(result)
```

#### 2. [掌握]三种常用匹配方式

* **`re.match()`**：从字符串开头尝试匹配。
* **`re.search()`**：扫描整个字符串，返回第一个匹配结果。
* **`re.findall()`**：扫描整个字符串，返回所有匹配结果列表。
* **记忆口诀**：`match` 看开头，`search` 找第一个，`findall` 找所有。

```python
# 导入 re 模块。
import re

# 准备文本。
# 文本开头是“订单号”，中间和后面各有一个手机号。
text = "订单号: A1001, 手机号: 13800138000, 备用: 13900139000"

# match 只从字符串开头匹配。
# 因为 text 开头不是 11 位数字，所以结果是 None。
print(re.match(r"\d{11}", text))

# search 会扫描整个字符串，返回第一个匹配到的结果。
# .group() 用来取出匹配对象里的真实文本。
# 预期输出：13800138000
print(re.search(r"\d{11}", text).group())

# findall 会扫描整个字符串，返回所有符合规则的内容。
# 预期输出：['13800138000', '13900139000']
print(re.findall(r"\d{11}", text))
```

#### 3. [互动提问]

* **问题 1**：`match` 和 `search` 最大区别是什么？
  * **答案**：`match` 只从字符串开头匹配；`search` 会扫描整个字符串并返回第一个匹配结果。
* **问题 2**：如果要提取一段文本中的所有手机号，用哪个函数更合适？
  * **答案**：用 `re.findall()` 更合适。
* **问题 3**：`findall()` 常见返回结果是什么类型？
  * **答案**：列表。

### 四. 正则表达式常用规则

#### 1. [掌握]匹配单个字符

| 规则 | 含义 |
| --- | --- |
| `.` | 匹配任意 1 个字符，默认不包含换行 |
| `[abc]` | 匹配 `a`、`b`、`c` 中任意 1 个字符 |
| `[^abc]` | 匹配除 `a`、`b`、`c` 以外任意 1 个字符 |
| `\d` | 匹配数字 |
| `\D` | 匹配非数字 |
| `\s` | 匹配空白字符 |
| `\S` | 匹配非空白字符 |
| `\w` | 匹配普通字符，如字母、数字、下划线、汉字 |
| `\W` | 匹配非普通字符 |

```python
# 导入 re 模块。
import re

# 文本中有 3 个“大写字母 + 两位数字”的编号。
text = "A12 B08 C99"

# [A-Z] 表示匹配 1 个大写字母。
# \d 表示匹配 1 个数字。
# \d\d 表示连续匹配 2 个数字。
# 整体规则 [A-Z]\d\d 表示：1 个大写字母 + 2 个数字。
result = re.findall(r"[A-Z]\d\d", text)

# 预期输出：['A12', 'B08', 'C99']
print(result)
```

#### 2. [掌握]匹配多个字符

| 规则 | 含义 |
| --- | --- |
| `*` | 前一个字符出现 0 次或多次 |
| `+` | 前一个字符出现 1 次或多次 |
| `?` | 前一个字符出现 0 次或 1 次 |
| `{m}` | 前一个字符出现 m 次 |
| `{m,n}` | 前一个字符出现 m 到 n 次 |

* **重点**：量词管的是前一个字符，或者前一个括号里的整体。

```python
# 导入 re 模块。
import re

# 文本中包含手机号、编号和价格。
text = "手机号: 13800138000, 编号: A1001, 价格: 1999"

# \d+ 表示连续 1 个或多个数字。
# 它会把手机号、编号中的数字、价格都提取出来。
print(re.findall(r"\d+", text))

# \d{11} 表示连续 11 位数字。
# 它更适合提取手机号这种固定长度数字。
print(re.findall(r"\d{11}", text))

# A\d{4} 表示以 A 开头，后面跟 4 位数字。
# 它可以提取 A1001。
print(re.findall(r"A\d{4}", text))
```

#### 3. [掌握]匹配指定字符串开头或结尾

| 规则 | 含义 |
| --- | --- |
| `^` | 匹配字符串开头 |
| `$` | 匹配字符串结尾 |

* **提取数据**：可以只写核心规则。
* **校验数据**：通常要加 `^` 和 `$`，保证整个字符串完整符合规则。

```python
# 导入 re 模块。
import re

# 准备多个待校验的字符串。
# 第一个是完整手机号。
# 第二个前面多了“电话”两个字。
# 第三个数字位数太长。
phones = ["13800138000", "电话13800138000", "13800138000123"]

# 遍历列表，逐个判断是否是完整手机号。
for phone in phones:
    # ^ 表示必须从字符串开头开始匹配。
    # 1 表示第一位必须是数字 1。
    # \d{10} 表示后面必须还有 10 位数字。
    # $ 表示必须匹配到字符串结尾，不能多出其他字符。
    print(phone, bool(re.match(r"^1\d{10}$", phone)))
```

#### 4. [掌握]提取分组数据

* **分组符号**：`()`
* **作用**：把完整匹配结果中的某些部分单独提取出来。

```python
# 导入 re 模块。
import re

# 准备包含日期的文本。
text = "订单日期: 2026-05-13"

# (\d{4}) 是第 1 个分组，用来提取年份。
# (\d{2}) 是第 2 个分组，用来提取月份。
# (\d{2}) 是第 3 个分组，用来提取日期。
result = re.search(r"(\d{4})-(\d{2})-(\d{2})", text)

# group() 获取完整匹配结果：2026-05-13。
print(result.group())

# group(1) 获取第 1 个分组：2026。
print(result.group(1))

# group(2) 获取第 2 个分组：05。
print(result.group(2))

# group(3) 获取第 3 个分组：13。
print(result.group(3))
```

#### 5. [理解]贪婪和非贪婪模式

* **贪婪模式**：在整个表达式匹配成功的前提下，尽可能多地匹配。
* **非贪婪模式**：在整个表达式匹配成功的前提下，尽可能少地匹配。
* **常见写法**：
  * 贪婪：`.*`、`.+`
  * 非贪婪：`.*?`、`.+?`

```python
# 导入 re 模块。
import re

# 准备一段模拟 HTML 标题的文本。
html = "<title>首页</title><title>商品详情</title>"

# 贪婪模式：.* 会尽可能多地匹配。
# 可能从第一个 <title> 一直匹配到最后一个 </title>。
print(re.findall(r"<title>.*</title>", html))

# 非贪婪模式：.*? 会尽可能少地匹配。
# 可以分别提取每一个 title 标签。
print(re.findall(r"<title>.*?</title>", html))
```

#### 6. [互动提问]

* **问题 1**：`\d{11}` 表示什么？
  * **答案**：连续 11 位数字。
* **问题 2**：为什么校验手机号时要写 `^1\d{10}$`，而不是只写 `\d+`？
  * **答案**：`\d+` 只表示连续数字，不限制长度，也不限制字符串前后是否还有其他内容；`^1\d{10}$` 可以保证整个字符串是完整手机号格式。
* **问题 3**：分组有什么用？
  * **答案**：可以从完整匹配结果中单独提取某些部分，例如日期中的年、月、日。
* **问题 4**：如果正则匹配结果太长，应该优先检查什么？
  * **答案**：检查是否使用了贪婪模式，比如 `.*`，必要时改成非贪婪 `.*?`。

### 五. 正则表达式综合案例：RAG 文档清洗

#### 1. [掌握]案例需求

给定一段原始文档文本，完成：

1. 提取手机号。
2. 删除页码。
3. 删除内部资料标记。
4. 删除页脚。
5. 压缩连续多个空行。

#### 2. [掌握]代码实现

```python
# 导入 re 模块。
# 本案例会用到 findall 提取数据，也会用到 sub 替换/删除文本。
import re

# raw 是一段模拟的 RAG 原始文档。
# 文本中包含页码、内部资料标记、手机号、问题内容、重复空行和页脚。
raw = """
第 1 页
【内部资料】课程答疑记录

学生手机号：13800138000
问题：re.match 和 re.search 有什么区别？


页脚：仅供学习
"""

# 提取手机号。
# \d{11} 表示连续 11 位数字。
# findall 会返回所有符合规则的手机号列表。
phones = re.findall(r"\d{11}", raw)

# 删除页码。
# 第\s*\d+\s*页 可以匹配“第1页”或“第 1 页”。
# 替换成空字符串，表示删除匹配到的内容。
cleaned = re.sub(r"第\s*\d+\s*页", "", raw)

# 删除【内部资料】这类标记。
# .*? 使用非贪婪匹配，避免一次性匹配过多内容。
cleaned = re.sub(r"【.*?】", "", cleaned)

# 删除页脚所在行。
# 页脚：.* 表示从“页脚：”开始匹配到该行结束。
cleaned = re.sub(r"页脚：.*", "", cleaned)

# 压缩重复空行。
# \n{2,} 表示连续 2 个或更多换行。
# 替换成一个换行，让文本更干净。
# strip() 用来去掉首尾多余空白。
cleaned = re.sub(r"\n{2,}", "\n", cleaned).strip()

# 打印提取到的手机号。
print(phones)

# 打印清洗后的文本。
print(cleaned)
```

#### 3. [互动提问]

* **问题 1**：RAG 文档清洗中，为什么要删除页码、页脚、重复空行？
  * **答案**：这些内容通常不是正文知识，会干扰后续切分、检索和回答效果。
* **问题 2**：`re.sub()` 的作用是什么？
  * **答案**：按照正则规则查找内容，并替换成指定内容；如果替换成空字符串，就相当于删除。

### 六. MySQL 数据库基础

#### 1. [掌握]数据库、数据表、字段

* **数据库**：存储和管理数据的系统。
* **数据表**：数据库中保存某一类数据的结构。
* **字段**：表中的列，用来描述记录的某个属性。
* **记录**：表中的一行数据。

#### 2. [掌握]SQL 分类

| 分类 | 全称 | 作用 | 常见关键字 |
| --- | --- | --- | --- |
| DDL | Data Definition Language | 定义数据库和表结构 | `CREATE`、`DROP`、`ALTER` |
| DML | Data Manipulation Language | 操作表数据 | `INSERT`、`UPDATE`、`DELETE` |
| DQL | Data Query Language | 查询表数据 | `SELECT` |
| DCL | Data Control Language | 权限控制 | 了解即可 |

* **记忆口诀**：
  * DDL：建结构。
  * DML：改数据。
  * DQL：查数据。

#### 3. [互动提问]

* **问题 1**：MySQL 和数据库是一个东西吗？
  * **答案**：不是。数据库是一个大类，MySQL 是关系型数据库管理系统的一种。
* **问题 2**：`CREATE TABLE` 属于 DDL、DML、DQL 中哪一类？
  * **答案**：DDL，因为它是在创建表结构。
* **问题 3**：`SELECT` 属于哪一类 SQL？
  * **答案**：DQL，因为它用于查询数据。

### 七. DDL：创建数据库和表

#### 1. [掌握]创建电商示例数据库和表

下面的 `category` 和 `product` 是今天课堂统一使用的电商示例表，需要同学们自己创建。后面的单表查询和多表查询都会基于这两张表展开。

```sql
-- 创建一个今天练习专用的数据库。
-- day06_shop 是数据库名，表示 Day06 的电商示例库。
-- DEFAULT CHARSET utf8mb4 用来支持中文，避免商品名、分类名出现乱码。
CREATE DATABASE day06_shop DEFAULT CHARSET utf8mb4;

-- 切换到 day06_shop 数据库。
-- 后面创建表和插入数据都会在这个库里完成。
USE day06_shop;

-- 创建分类表 category。
-- 作用：保存商品分类，例如“手机”“电脑配件”“办公用品”。
CREATE TABLE category (
    -- 分类 id，主键，自增。
    -- 主键的作用是唯一标识一条分类记录。
    id INT PRIMARY KEY AUTO_INCREMENT,

    -- 分类名称，最多 50 个字符，不能为空。
    name VARCHAR(50) NOT NULL
);

-- 创建商品表 product。
-- 作用：保存具体商品信息。
CREATE TABLE product (
    -- 商品 id，主键，自增。
    id INT PRIMARY KEY AUTO_INCREMENT,

    -- 商品名称，不能为空。
    name VARCHAR(100) NOT NULL,

    -- 商品价格，保留两位小数。
    -- 金额类数据建议使用 DECIMAL，结果更精确。
    price DECIMAL(10, 2) NOT NULL,

    -- 商品库存，表示当前剩余数量。
    stock INT NOT NULL,

    -- 商品所属分类 id。
    -- 后面做多表查询时，会用它关联 category 表的 id。
    category_id INT
);
```

#### 2. [互动提问]

* **问题 1**：创建表之前为什么要先 `USE day06_shop`？
  * **答案**：因为要指定后续建表和操作数据所在的数据库。
* **问题 2**：`category_id` 的作用是什么？
  * **答案**：表示商品所属分类的 id，用来关联 `category` 表中的 `id`。

### 八. DML：插入、修改、删除数据

#### 1. [掌握]插入示例数据

```sql
-- 向分类表插入 3 条分类数据。
-- 后面的商品会通过 category_id 归属到这些分类中。
INSERT INTO category(name) VALUES
('手机'),
('电脑配件'),
('办公用品');

-- 向商品表插入 5 条商品数据。
-- 字段顺序是：商品名称、商品价格、库存数量、所属分类 id。
-- category_id 为 1 表示手机，为 2 表示电脑配件，为 3 表示办公用品。
INSERT INTO product(name, price, stock, category_id) VALUES
('iPhone 15', 5999.00, 100, 1),
('机械键盘', 299.00, 50, 2),
('无线鼠标', 99.00, 80, 2),
('笔记本支架', 59.00, 120, 3),
('安卓充电线', 29.90, 200, 1);
```

#### 2. [掌握]修改数据

```sql
-- 把“机械键盘”的价格改成 279。
-- WHERE name = '机械键盘' 表示只修改这一条商品。
-- 如果没有 WHERE，可能会把整张 product 表的商品价格都改掉。
UPDATE product SET price = 279.00 WHERE name = '机械键盘';
```

#### 3. [掌握]删除数据

```sql
-- 删除“无线鼠标”这条商品数据。
-- WHERE name = '无线鼠标' 表示只删除指定商品。
-- 如果没有 WHERE，可能会删除整张 product 表的数据。
DELETE FROM product WHERE name = '无线鼠标';
```

#### 4. [互动提问]

* **问题 1**：`UPDATE product SET price = 99;` 错在哪里？
  * **答案**：缺少 `WHERE` 条件，会把整张表所有商品价格都改成 99。
* **问题 2**：删除数据时为什么也要写 `WHERE`？
  * **答案**：因为没有 `WHERE` 会删除整张表的数据，风险很高。

### 九. DQL：单表查询

#### 1. [掌握]基础查询

```sql
-- 查询 product 表中的所有字段。
-- * 表示所有列，适合检查表中完整数据。
SELECT * FROM product;

-- 只查询商品名称和价格。
-- 当只需要部分字段时，不建议总是使用 *。
SELECT name, price FROM product;
```

#### 2. [掌握]条件查询

```sql
-- 查询价格大于 100 的商品。
-- WHERE 用于筛选符合条件的数据。
SELECT *
FROM product
WHERE price > 100;
```

#### 3. [掌握]排序查询

```sql
-- 查询所有商品，并按照价格从高到低排序。
-- ORDER BY 用于排序。
-- DESC 表示降序，从大到小。
SELECT *
FROM product
ORDER BY price DESC;
```

#### 4. [掌握]聚合函数

```sql
-- 统计商品数量和平均价格。
-- COUNT(*) 用于统计行数。
-- AVG(price) 用于计算平均价格。
-- AS 用于给结果列起别名，让结果更容易看懂。
SELECT COUNT(*) AS product_count, AVG(price) AS avg_price
FROM product;
```

#### 5. [掌握]分组查询

```sql
-- 按分类统计商品数量。
-- GROUP BY category_id 表示按照分类 id 分组。
-- COUNT(*) 会统计每个分类分组中有多少条商品记录。
SELECT category_id, COUNT(*) AS product_count
FROM product
GROUP BY category_id;
```

#### 6. [掌握]LIMIT 查询

```sql
-- 查询库存最低的前 3 个商品。
-- ORDER BY stock ASC 表示按照库存从低到高排序。
-- LIMIT 0, 3 表示从第 0 条开始取 3 条。
SELECT *
FROM product
ORDER BY stock ASC
LIMIT 0, 3;
```

#### 7. [理解]SQL 逻辑执行顺序

常见逻辑顺序：

```text
FROM -> WHERE -> GROUP BY -> 聚合函数 -> HAVING -> SELECT -> ORDER BY -> LIMIT
```

* **面试点**：SQL 书写顺序和逻辑执行顺序不完全一样。

#### 8. [互动提问]

* **问题 1**：查询价格大于 100 的商品，用哪个关键字？
  * **答案**：`WHERE`。
* **问题 2**：查询每个分类下商品数量，需要使用什么？
  * **答案**：`GROUP BY` 和 `COUNT(*)`。
* **问题 3**：查询库存最低的前 3 个商品，为什么要先 `ORDER BY stock ASC`？
  * **答案**：因为要先把库存从低到高排好，再用 `LIMIT` 取前 3 条。

### 十. DQL：多表查询

#### 1. [理解]为什么需要多表查询

* 真实业务中，不会把所有数据都塞进一张表。
* 商品表保存商品自身信息，分类表保存分类信息。
* 商品表通过 `category_id` 和分类表的 `id` 建立关系。
* **核心思想**：按关系把多张表临时拼成一张结果表，再按照单表查询思路处理。

#### 2. [掌握]内连接

```sql
-- 查询商品名称、价格、分类名称。
-- 商品名称和价格来自 product 表。
-- 分类名称来自 category 表。
SELECT
    -- p.name 表示 product 表中的 name 字段。
    -- AS product_name 表示给结果列起别名，叫 product_name。
    p.name AS product_name,

    -- 查询商品价格。
    p.price,

    -- c.name 表示 category 表中的 name 字段。
    -- AS category_name 表示给分类名称起别名。
    c.name AS category_name

-- product p 表示给 product 表起别名 p。
FROM product p

-- INNER JOIN 表示内连接。
-- category c 表示给 category 表起别名 c。
-- ON 后面写连接条件。
-- p.category_id = c.id 表示商品表的分类 id 等于分类表的 id。
INNER JOIN category c ON p.category_id = c.id;
```

* **内连接特点**：只保留两张表中能匹配成功的数据。

#### 3. [掌握]左连接

```sql
-- 查询所有分类及其商品。
-- 即使某个分类下面暂时没有商品，左连接也会保留这个分类。
SELECT
    -- 查询分类名称。
    c.name AS category_name,

    -- 查询商品名称。
    -- 如果该分类下没有商品，这里可能显示 NULL。
    p.name AS product_name

-- 左表是 category，所以 LEFT JOIN 会保留所有分类。
FROM category c

-- 按照分类 id 和商品表中的 category_id 关联。
LEFT JOIN product p ON c.id = p.category_id;
```

* **左连接特点**：保留左表全部数据，右表匹配不到时显示 `NULL`。

#### 4. [掌握]子查询

```sql
-- 查询价格高于全表平均价格的商品。
-- 外层查询负责查询商品。
SELECT *
FROM product
WHERE price > (
    -- 子查询先计算全表商品平均价格。
    -- 外层 WHERE 再拿商品价格和平均价格比较。
    SELECT AVG(price)
    FROM product
);
```

* **核心理解**：括号里的查询先执行，外层查询再使用它的结果。

#### 5. [互动提问]

* **问题 1**：为什么商品表不直接重复保存分类名称？
  * **答案**：避免数据重复，方便统一维护分类信息。
* **问题 2**：多表查询中 `ON p.category_id = c.id` 的作用是什么？
  * **答案**：指定两张表的连接条件，让商品能找到对应分类。
* **问题 3**：如果多表查询漏写连接条件，会出现什么问题？
  * **答案**：会产生大量错误组合，也就是笛卡尔积。
* **问题 4**：内连接和左连接的区别是什么？
  * **答案**：内连接只保留两边匹配成功的数据；左连接保留左表全部数据，右表匹配不到时显示 `NULL`。

#### 2. 易错点：错误与正确对照

| 易错点 | 错误写法 / 错误理解 | 正确写法 / 正确理解 |
| --- | --- | --- |
| 正则字符串 | `"\d{11}"` 在复杂场景中可能受转义影响 | 推荐写 `r"\d{11}"` |
| `match` 用法 | 认为 `match` 会全文搜索 | `match` 只从字符串开头匹配 |
| 手机号校验 | 用 `\d+` 校验手机号 | 用 `^1\d{10}$` 校验完整手机号 |
| 量词作用对象 | 认为 `{11}` 管前面所有内容 | 量词只管前一个字符或前一个分组 |
| 贪婪匹配 | 用 `<title>.*</title>` 提取多个标签 | 用 `<title>.*?</title>` 分别提取 |
| 分组提取 | 只会取完整匹配结果 | 用 `group(1)`、`group(2)` 提取分组 |
| 建表位置 | 没有 `USE` 数据库就建表 | 先 `USE day06_shop` 再建表 |
| 修改数据 | `UPDATE product SET price = 99;` | `UPDATE product SET price = 99 WHERE name = 'xxx';` |
| 删除数据 | `DELETE FROM product;` | `DELETE FROM product WHERE name = 'xxx';` |
| 多表查询 | 忘记写 `ON` 连接条件 | 写清 `ON p.category_id = c.id` |
| 字段同名 | 多表查询直接写 `name`，不知道来自哪张表 | 使用表别名，如 `p.name`、`c.name` |
| 分组统计 | 查询每类商品数量时只写 `COUNT(*)` | 使用 `GROUP BY category_id` 后再 `COUNT(*)` |

#### 3. 今日必须记住的几句话

* 正则表达式是用规则匹配一类字符串。
* `match` 看开头，`search` 找第一个，`findall` 找所有。
* 提取看规则，校验看完整，校验通常要写 `^` 和 `$`。
* DDL 建结构，DML 改数据，DQL 查数据。
* `UPDATE` 和 `DELETE` 不写 `WHERE` 非常危险。
* 多表查询的核心是按关系把多张表临时拼成一张结果表。
