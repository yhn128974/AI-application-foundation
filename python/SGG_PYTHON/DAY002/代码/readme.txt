
程序常见的问题
    语法错误
        程序在对语法进行解析阶段就发现问题  程序不会执行
    异常
        程序的语法是正确的，在运行它的时候，也有可能发生错误。运行期检测到的错误被称为异常

异常处理
    异常处理的目的：不是为了规避异常的发生，而是当程序发生异常了，提供对异常的处理方案，让程序不终止，可以继续向下执行
        如果不对程序运行的过程中，发生的异常进行处理，程序默认的处理方式是将异常打印到控制台，
        程序也会终止，异常后面的代码不会被执行


    基本语法
        try:
            可能发生异常的代码
        except:
            如果发生异常，对异常进行处理的代码
    说明：
        如果发生了异常，那么try后面的代码将不再被执行，直接执行except块中对异常进行处理的代码
        如果没有发生异常，那么except块中的代码将不会被执行，直接执行异常处理后面的代码

当程序运行的过程中，如果发生异常，底层原理
    如果程序执行的过程中，发生了异常，底层会创建一个对应异常类型，然后将这个异常对象向上抛出(raise)
    当调用者接收到异常对应之后，可以通过except代码块对异常对象进行捕获,在except代码块中对异常进行处理；如果没有被except捕获，那么异常会继续向上抛出，
    直到交给解释器，解释器默认处理方式是将异常信息打印到控制台，程序终止

except可以针对不同类型的异常进行处理
    语法：
        try:
            可能发生异常的代码块
        except 异常类型1 as 别名:
            处理方式1
        except 异常类型2 as 别名:
            处理方式2
        except (异常类型3,异常类型4,异常类型5) as 别名:
            处理方式3
        except:
            处理方式4
    说明：
        如果没有发生异常，程序会忽略except中的代码，继续向下执行。
        如果发生了异常，会忽略try中剩余代码，根据异常类型匹配到相应的 except 并执行其中的代码。
        如果发生了异常，且异常类型无法和任何except匹配，异常将向外传递。
        一个except可以同时处理多个异常，将这些异常放在一个元组中。
        最后一个 except 可以忽略异常类型，它将被作为通配符使用。

else语句块
    可选地将else放在所有except之后。如果try中代码没有发生异常，将执行 else 中的代码
    语法：
        try:
            可能发生异常的代码块
        except 异常类型1 as 别名:
            处理方式1
        except 异常类型2 as 别名:
            处理方式2
        except (异常类型3,异常类型4,异常类型5) as 别名:
            处理方式3
        except:
            处理方式4
        else:
            try中代码没有发生异常，将执行 else 中的代码

    注意： 将代码放到else中和放到try块中，执行效果是一样的，但是放到else中，可以明确说明，这里的代码是没有发生异常的情况下才执行，更清洗

finally语句
    不管是否发生异常，都会执行的代码，一般将资源释放的代码放到finally语句中

    语法：
        try:
            可能发生异常的代码块
        except 异常类型1 as 别名:
            处理方式1
        except 异常类型2 as 别名:
            处理方式2
        except (异常类型3,异常类型4,异常类型5) as 别名:
            处理方式3
        except:
            处理方式4
        else:
            try中代码没有发生异常，将执行 else 中的代码
        finally:
            不管是否发生异常，都会执行的代码

    注意: 大部分情况下，将代码放到finally中和放到异常处理代码块外效果是一样的

          直接放在try-except结构外面的代码只会在try-except结构正常执行完毕后才会执行，
          如果在try块中出现异常且没有被except块捕获，或者在except块中出现了新的异常导致程序终止，那么这部分代码将不会被执行。

异常的传递
    try嵌套或者函数的嵌套定义-- 一层一层向外传递
    如果存在函数的嵌套调用  --- 沿着函数调用的方向反向传递

with
    语法
        with expression as variable:
            # 代码块
    说明
        with 是关键字
        as  是关键字
        expression:是一个对象或者是函数调用，要求返回的内容类型必须是上下文管理器对象类型
               上下文管理器类中有两个方法必须提供：__enter__和__exit__方法。

        variable：是可选的，用于存储expression的__enter__方法的返回值

    执行原理
        当执行with语句时，会调用expression对象的__enter__方法。
        __enter__ 方法的返回值可以被存储在 variable 中（如果有），以供 with 代码块中使用。
        __enter__方法的返回值一般是self(当前上下文管理器对象)
        执行with代码块中的内容
        当代码块执行完毕之后，不管是否发生异常，都会执行上下文管理器对象的__exit__方法，在__exit__方法中，将资源释放掉
